INSTRUMENT PREFLIGHT — MANDATORY FOR FORMAL / LOGGED RUNS   [TOOL-004]
-----------------------------------------------------------------

This prompt is part of the audit instrument. Establish the exact instrument version BEFORE
substantive retrieval, extraction, analysis, or verdict work begins.

A successful fetch indicator, correct repository path, branch label, plausible line count,
matching rendered metadata, or internally self-consistent page does NOT by itself establish
that the intended/current artifact was retrieved. A mutable remote reference can return a
historical representation that is internally self-consistent in every visible field.

PROMPT IDENTITY MARKERS

  - CITATION NETWORK AUDIT PROMPT: DETECTING FUNCTIONAL CITATION CARTELS AND ADJACENT FIELD

These markers confirm the prompt family / expected structural features. They do NOT by
themselves establish version currency: an older version may share the same title or markers.

1. RECORD THE INSTRUMENT ACTUALLY IN CONTEXT.

   Record, where available:

   - canonical prompt path or supplied filename;
   - retrieval form: PASTED / ATTACHED / IMMUTABLE REMOTE / MUTABLE REMOTE;
   - requested branch or ref;
   - intended immutable commit/ref, if the run claims a repository version;
   - resolved commit SHA;
   - resolved blob/content hash, or a locally computed cryptographic content hash;
   - exact line count and byte count;
   - prompt identity markers present / absent.

   If a pasted or attached artifact is itself the declared instrument under test, its computed
   content hash may serve as its identity. Do not claim it is the current canonical repository
   version unless that relationship is independently established.

2. MUTABLE-REFERENCE / CURRENCY RULE.

   A path such as /blob/main/, /blob/master/, latest, or another moving branch/ref is a LOCATOR,
   not an immutable version identity.

   Ordinary exploratory work may use a mutable locator with the limitation preserved.

   A FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE run that claims the current repository
   instrument must establish an immutable intended identity independently of the mutable-content
   fetch. Acceptable examples include:

   - an operator-supplied immutable commit permalink;
   - a branch-head / repository-history lookup independent of the content retrieval, followed by
     retrieval of the file at that immutable commit;
   - a second retrieval path that does not reuse the same cache/index, confirmed against an
     immutable commit/blob identity.

   A commit/hash/line-count reported only by the SAME potentially stale rendered representation
   is NOT independent currency evidence.

   If no independent immutable anchor can be established and no explicit collision is observed,
   classify:

     INSTRUMENT VERSION UNVERIFIED

   Such a run may be exploratory but may not count as formal regression or benchmark evidence
   for a claimed canonical version.

3. VERSION-COLLISION ATTRIBUTION GATE.

   If the retrieved representation disagrees with an expected hash, immutable ref, size, line
   count, marker set, or independently established version, classify only:

     VERSION COLLISION — UNRESOLVED

   A failed identity check proves a VERSION MISMATCH. It does NOT establish where the stale
   representation lives. Do NOT conclude from the conflicting retrieval alone:

     REPOSITORY STALE
     RETRIEVAL STALE
     LOCAL COPY STALE
     OPERATOR COPY STALE

   Attribution requires a SECOND, INDEPENDENT discriminator, such as:

   - an immutable commit/blob lookup;
   - repository/file history;
   - a second retrieval path that does not reuse the same cache/index;
   - direct operator confirmation supported by an immutable identity;
   - a locally supplied file whose hash can be compared independently.

   Internal self-consistency is NOT an independent discriminator. A stale representation may
   have a mutually consistent path, branch label, line count, byte size, line gutter, content,
   and rendered repository metadata because all were produced from the same stale snapshot.

4. DISPOSITION.

   FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE RUN:
     - IDENTITY CONFIRMED against the intended immutable instrument -> continue.
     - VERSION COLLISION — UNRESOLVED -> STOP before substantive execution.
     - INSTRUMENT VERSION UNVERIFIED -> exploratory execution may occur, but the run may not be
       logged as evidence for the claimed canonical instrument.

   ORDINARY EXPLORATORY RUN:
     - May continue with INSTRUMENT VERSION UNVERIFIED when no collision is observed.
     - If a collision is observed, do not make claims about repository/instrument state until
       the collision is independently resolved.

5. REQUIRED RUN-HEADER LINE.

   Emit this before the substantive body:

   INSTRUMENT PREFLIGHT: [path/file] @ commit [SHA/UNAVAILABLE] | blob/hash
   [HASH/UNAVAILABLE] | [N] lines | [N] bytes | markers [PRESENT/ABSENT] |
   [IDENTITY CONFIRMED / INSTRUMENT VERSION UNVERIFIED /
   VERSION COLLISION — UNRESOLVED]

   If VERSION COLLISION — UNRESOLVED is returned, also state the conflicting identities and the
   independent discriminator required to resolve them. Do not silently choose one.

GOVERNING RULE:

  A failed identity check proves a version mismatch, not where the mismatch lives.

-----

PURPOSE

Use this prompt to audit whether a field, subfield, or contested claim is supported by a
healthy evidence base or by a functionally closed citation network.

The goal is not to prove that individual researchers acted in bad faith. The goal is to test
whether the literature's apparent consensus is produced by converging evidence, or by repeated
citation of the same premise, same proxies, same review hubs, same author clusters, and same
neglected adjacent literatures.

This prompt is designed for fields where a domain expert suspects that:
- a small founding cluster dominates the literature;
- weak proxy studies are being cited as if they directly measured the target construct;
- review papers are laundering a premise into "settled science";
- adjacent fields with direct expertise are ignored;
- recent papers continue recycling old claims rather than testing the decisive question.

-----

IMPORTANT DEFINITION

In this prompt, "citation cartel" does not require proof of secret coordination, illegal
collusion, or private bad faith.

It means a functional citation structure: a small group of papers, authors, journals,
theoretical frameworks, or institutional networks repeatedly cite one another, recycle the
same load-bearing premise, neglect adjacent literatures, and convert repetition into apparent
consensus.

Use "cartel" as a structural diagnosis, not a motive claim.

Preferred formal terms:
- functionally closed citation network
- self-referential citation cluster
- citation laundering pathway
- premise-laundering hub
- adjacent-field neglect
- unsupported consensus construction

Use "citation cartel" only when the evidence supports closure, premise recycling, and
systematic exclusion of relevant outside evidence.

-----

Provide:
1. A one-paragraph description of the field or subfield.
2. The central contested claim.
3. Any founding papers or review papers you already know.
4. Any adjacent fields you suspect were ignored.
5. Any databases or citation sources available to you.

Do not rely on any model to invent exact citation metrics. If exact citation data are
unavailable, require the model to label numbers as rough estimates or source leads.

COMPACT VOCABULARY Full rules: shared_primitives.txt

VERIFICATION STATE  -  how thoroughly a source has been checked. This is separate from
evidence type.

- LOCATED: source exists and metadata is confirmed; content is unverified.
- ABSTRACT-CONFIRMED: abstract supports relevance; methods and results are not verified.
- FULL-TEXT-CONFIRMED: full text was read and directly supports the specific claim.
- RECEPTION-CONFIRMED: replies, replications, corrections, retractions, citation graphs, or
  citation contexts were checked against retrieved sources.
- CONTESTED: credible disagreement exists; who is correct remains unresolved.
- REBUTTED: later work directly and substantially challenges the source and the challenge was
  not evidently answered.
- PROVISIONAL: access or retrieval is insufficient, including unverified model memory,
  unresolved leads, or model-estimated network metrics.

- CROSS-SOURCE-CONFIRMED: an ATTRIBUTION relationship was checked by reading BOTH the
  downstream text and the audited source  -  plus a successor or alternative source where one
  is implicated  -  and comparing what is claimed against what each actually supports. This is
  a distinct verification act: not reception checking (how a source fared) and not full-text
  checking (what one source says), but whether a downstream text has assigned a claim to a
  source that supports it. Use for every MISATTRIBUTED or ATTRIBUTED ELSEWHERE classification
  you actually verified.

DO NOT INVENT VERIFICATION STATES. The list above is the whole vocabulary. Live runs have
produced "ESTABLISHED FROM SOURCE," "RECONSTRUCTION FROM SOURCE," and similar ad-hoc labels.
Each reads as authoritative, none is defined anywhere, and a downstream stage cannot tell what
was actually checked. If no state fits what you did, describe it in a sentence rather than
coining a label  -  an undefined state is worse than plain prose.

DERIVATION MODE  -  how a reported value was produced. This is separate from verification
state, evidence type, and dimension disposition.

- COMPUTED-FROM-RETRIEVED: the value was computed from retrieved inputs by a rule stated in
  the output. Report all five receipts together: computation rule; numerator; denominator;
  retrieval coverage of the required inputs; and the canonical verification state of those
  inputs. If any receipt is missing, the value is PROVISIONAL.

COMPUTED-FROM-RETRIEVED is not a verification state and does not upgrade its inputs. A metric
may therefore be reported as, for example, "Verification state: RECEPTION-CONFIRMED;
Derivation mode: COMPUTED-FROM-RETRIEVED." Never coin GRAPH-VERIFIED, CONTEXT-VERIFIED,
SOURCE-VERIFIED, RECEPTION-VERIFIED, or another compound substitute.

For a field that is an author reconstruction rather than a retrieval, write "author
reconstruction from [source field]." That is a description, not a verification state.

ATTRIBUTION CLASSIFICATIONS FOR STANDALONE USE:

- MISATTRIBUTED: the downstream text cites the audited source for a claim that source cannot
  support.
- ATTRIBUTED ELSEWHERE: the actual supporting source is cited correctly, and the audited
  source is not assigned the unsupported claim.

Rules:

1. Never report a verification state above what was actually checked.
2. Evidence type and verification state are separate axes; report both.
3. FULL-TEXT-CONFIRMED and RECEPTION-CONFIRMED may both apply.
4. Apply the ladder symmetrically to sources supporting and opposing the claim.
5. A PROVISIONAL source or network metric may not anchor a MAJOR or FATAL finding.

FAILURE LOCATION  -  where the failure actually lives:

- PAPER: the foundational source itself overclaims or rests on inadequate evidence.
- CITATION: later literature inflates, launders, or recycles the claim.
- PR / MEDIA: communications or coverage strip caveats or broaden the claim.
- MODEL / RETRIEVAL: summarizers or search systems reproduce the inflated version.
- MIXED: more than one layer contributes; specify which layer contributes what.

Attacking a defensible paper for downstream inflation is a category error. Classify the
responsible layer honestly.

RECEPTION-MODULE CONFIRMATION RULE

Any load-bearing claim in this audit  -  hub dominance, internal-citation density, claim
mutation, amplification or ratchet behavior, or critique non-uptake  -  must be checked
against retrieved citation data before it is stated as fact. Do not assert it from model
memory.

Use the citation-reception module (OpenAlex + Semantic Scholar), together with direct source
retrieval where available. For each load-bearing source or network claim:

- Hub dominance and internal density (Sections A and F): confirm citation counts, citing-set
  overlap, and network edges from retrieved data rather than estimates.
- Claim mutation and amplification (Sections D and G): inspect citation-context snippets and,
  where load-bearing, the full citing texts. Check whether limiting language appears in early
  contexts and disappears downstream.
- Critique non-uptake (Section H): confirm the critique's citation count, whether
  dominant-cluster papers actually cite it, and whether formal replies or rebuttals exist.

Apply the compact verification vocabulary:

- Retrieved citation graph or citation contexts: RECEPTION-CONFIRMED.
- Metadata resolved but citing content unread: LOCATED.
- Model estimate or remembered network pattern: PROVISIONAL.

A claim is not RECEPTION-CONFIRMED merely because it sounds familiar. It must trace to an
actual retrieval query. Label quantitative and reception claims in the output as either:

- RECEPTION-CONFIRMED (retrieved via OpenAlex/S2); or
- PROVISIONAL  -  not confirmed / model estimate.

Citation-context snippets can establish that a formulation appears in the citing record, but a
load-bearing claim-mutation finding should be FULL-TEXT-CONFIRMED where the context is
ambiguous or the surrounding argument matters.

NO-ASSUME-SUPPRESSION

Low citation uptake of a critique has at least two explanations: the field marginalized valid
work, or the field discounted work that did not survive scrutiny. Do not resolve toward
suppression unless the critique's own reception has been checked. Low uptake of a REBUTTED
critique is expected, not evidence of functional closure.

SECTION E: ADJACENT FIELD ENGAGEMENT / NEGLECT

Run Steps 31–37 BEFORE examining the audited paper's references or citation network for
adjacent-field engagement. Step 38 is the first citation-inspection step.

31. LOCK THE CLAIM LAYERS.

State separately:

- exact source claim;
- weaker defensible source claim;
- downstream citation claim; and
- public, policy, clinical, professional, or elite-performance extrapolation, if any.

Do not use literature relevant to one layer to award engagement credit on another. Keep
source-level and downstream layers separate through generation, engagement classification,
scoring, and the final verdict.

32. STATE THE STRONGEST PLAUSIBLE RIVAL EXPLANATION.

For each claim layer, state the strongest live rival explanatory account that could explain
the same observed result while materially narrowing or defeating the audited inference. Do
not substitute the claim's bare logical negation. A mechanical negation can admit politically
opposite but evidentially irrelevant literatures by construction.

33. STATE THE ADJUDICATING OBSERVATIONS.

For the audited claim and the rival explanation, answer:

    What observation, measured with a method the relevant field would have to take seriously,
    would weaken, materially narrow, or defeat this explanation?

The purpose is not to create one supporting list and one opposing list. It is to identify
evidence capable of discriminating between live explanations.

34. GENERATE CANDIDATE FIELDS FROM BOTH EXPLANATIONS.

Name literatures capable of producing those adjudicating observations. Generate them from the
claim, construct, and rival structure—not from the bibliography and not from the auditor's
preferred account.

35. APPLY THE SAME CORE QUALIFICATION TEST.

Apply the same requirements to candidates generated from either direction:

- Measurement relevance: the literature measures the target construct, the rival mechanism,
  or a decisive boundary condition.
- Adjudicative capacity: it can produce evidence that distinguishes the live explanations or
  materially narrows one of them.
- Independence: its method, error structure, or evidence source is independent enough not
  simply to reproduce the audited field's load-bearing assumptions.
- Historical availability: relevant work existed, was mature enough to bear on the claim, was
  plausibly discoverable, and used translatable constructs or measures during the relevant
  publication window.

Political opposition, topical adjacency, or a generally compatible narrative does not
qualify a field. For example, harassment or attrition research may be relevant to
participation, retention, or practice-access claims. It does not automatically qualify as
adjudicating evidence for a mechanical or elite-performance ceiling claim unless its design
can distinguish that explanation through exposure matching, mediation, decomposition, or
another measurement capable of changing confidence in the mechanism.

If a candidate fails historical availability, do not award a healthy zero and do not penalize
the audited paper. Mark the candidate UNINFORMATIVE for that historical comparison.

36. MERGE, DEDUPLICATE, AND LOCK THE LIST.

Merge candidates from both directions, remove duplicates, and record why each surviving field
qualifies. Freeze the list before searching citations. Do not replace an absent field with a
more congenial field discovered later. Post hoc additions are allowed only when labeled POST
HOC and may not erase the result for the locked list.

The lock must operate at the level that can anchor the score. State exactly one:

- SOURCE-LOCK METHOD: LOCKED QUERY. Preferred. Before bibliography inspection, preregister a
  reproducible selection query whose output fixes the source list: database, exact query or
  concept identifier, date cutoff, ranking rule, N, deduplication rule, timestamp, and saved-
  result hash. Run it and lock its output.
- SOURCE-LOCK METHOD: LOCKED SOURCES. Before bibliography inspection, name the specific works
  and stable identifiers, with timestamp or hash.
- SOURCE-LOCK METHOD: POST HOC. Use when neither ex-ante route is feasible. Sources selected
  after bibliography inspection must be labeled POST HOC and may not independently anchor
  SCORED 2 or SCORED 3 on adjacent-field neglect; they may support SCORED 1.

Locking a field while choosing its exemplar sources after citation inspection is POST HOC,

RATCHET SCORING ROUTE

Do not score these questions as one compound dimension.

- Intervention-evidence ratchet: assess whether the literature continues strengthening an

- Model non-updating: assess whether the literature preserves the same causal or explanatory

  result, and later model behavior were not traced.

MODEL-IDENTITY AND TEMPORAL GATE

different causal branch cannot establish or reduce the model-non-updating score.

SECTION H: IGNORED CRITIQUE AND NON-UPTAKE

2. CRITIQUE RETRIEVAL.

3. RECEPTION OPPORTUNITY.

4. UPTAKE TEST.

- No critique found and critique production not reasonably expected: UNINFORMATIVE.

SECTION J2: THE CONCEDE TEST

Run this on every proposed network finding before scoring Section K or choosing the final
formal label.

FINDING-TARGET AND DOUBLE-COUNT GATE  [FAIL-MB-003]

Before applying the Concede Test:

1. Read the Target claim declared in every proposed standardized finding row. Do not assume
   all rows target map field 6 merely because the audit was supposed to.

2. If a row targets a different claim, mark:

   "MAP GAP: this finding targets [claim], not map field 6."

   Test the finding against its declared claim, but do not let it anchor the field-6 verdict
   until it has been re-aimed and the severity survives.

3. Do not count two labels on one underlying mismatch as two independent levers. In
   particular, a definitional-scope-creep row and a general claim-vs-measurement row resting
   on the same items are NESTED manifestations of one mechanism.

4. Preserve nested rows when they improve traceability, but count the mechanism once in
   Section K, once in the load-bearing list, and once when judging compounding. Shared
   evidence is not independent evidence.

Apply this same ownership rule to Section K dimensions. Every SCORED dimension must receive
one AGGREGATION STATUS:

- INDEPENDENT; or
- NESTED under [parent dimension].

When dimensions reuse evidence, the second must either identify the distinct evidence and
inferential work that supports independent scoring, or be NESTED under the parent that owns
the shared evidence. A nested dimension keeps its disposition and ordinal score for
traceability and counts as assessed for coverage, but is excluded from the aggregate risk
numerator and denominator. Distinct constructs may both remain in the inventory; shared
evidence is what bars additive scoring.

Required pre-Concede table:

| Finding | Declared target claim | Matches map field 6? | Same mechanism as another row? | Count separately? |
|---|---|---|---|---|

For each finding, ask:

IF THIS FINDING WERE FULLY CONCEDED  -  granted entirely, with no argument  -  WOULD THE CLAIM
NAMED IN MAP FIELD 6 STILL STAND?

- SURVIVES: the audited claim still stands. The observation may be a real network limitation,
  but it cannot anchor a high-risk verdict.
- NARROWS: the claim survives only in smaller epistemic scope  -  for example, the underlying
  proposition may remain possible, but the literature has not established it through the
  degree of independence or convergence claimed.
- DEFEATS: the map-field-6 claim does not follow. This is load-bearing.

Create a table:

| Finding | Concede test: SURVIVES / NARROWS / DEFEATS | Surviving claim if NARROWS |
|---|---|---|

NETWORK-SPECIFIC SCOPE RULE

Apply the test to the exact wording of field 6:

- If field 6 is an epistemic claim such as "independent converging evidence has established
  X," verified dependence, laundering, or absent direct tests can NARROW or DEFEAT that claim.
- If field 6 is the bare real-world proposition "X is true," a citation network usually cannot
  defeat the proposition by itself. It can show that the cited literature does not establish
  X. Do not silently convert an evidentiary failure into a truth verdict.

SCOPE-LOSS ASSESSMENT  -  REQUIRED FOR EVERY NARROWS RESULT

- INCIDENTAL NARROWING: the evidentiary claim remains substantially intact after a small
  precision or boundary correction.
- MATERIAL NARROWING: the asserted consensus, independence, breadth, or certainty is
  meaningfully reduced, while a weaker evidentiary claim survives.
- NEAR-DEFEAT NARROWING: only a trivial or practically different remainder survives.
  Reclassify as DEFEATS when it no longer supports the use under audit.

For each NARROWS result, add:

| Finding | Scope-loss level | Original claim | Surviving claim | What epistemic or practical work is lost? |
|---|---|---|---|---|

SCORING AND LABEL MAPPING

- A SURVIVES finding may not justify a dimension score of 3 or anchor the final formal label.
- A verified MATERIAL NARROWING finding may justify a serious-concern score where the
  dimension warrants it.
- A score of 3 or a DEFEATS finding requires adequately verified evidence.
- A PROVISIONAL metric or model-estimated network pattern may not independently anchor
  "functional citation cartel," "functionally closed citation network," or another MAJOR/FATAL
  finding.
- Do not sum duplicated manifestations of the same source dependence as if they were
  independent failures.
- A definitional-scope-creep row and a general claim-vs-measurement row resting on the same
  item mismatch count as one mechanism, not two levers.

Do not use this test to suppress genuine network weaknesses. Report SURVIVES findings, but
calibrate their severity and role in the verdict.

PROVISIONAL COVERAGE GATE

A formal network label initially requires:

- at least 70% of applicable dimensions SCORED, counting independent and nested dimensions as
  assessed for coverage; and
- no dimension essential to the proposed label left UNASSESSED.

The 70% value is PROVISIONAL. It is an engineering threshold for validation, not an
empirically established boundary. Record whether bands remain stable as coverage increases.
Do not describe 70% as validated.

A functional-closure label additionally requires verified topology or density, claim
transmission or premise recycling, and tested engagement with credible disconfirming evidence.
It cannot be generated from the percentage alone. Proxy mismatch, claim mutation, or a high
average across a small subset cannot substitute for those label-essential mechanisms.

A healthy/low-risk label requires affirmative evidence on the dimensions that could otherwise
establish closure. Missing graph data cannot support a healthy verdict.

PERCENTAGE BANDS

- 0%–20%: healthy or low-risk network
- >20%–40%: normal field clustering with some weaknesses
- >40%–60%: self-referential literature with significant blind spots
- >60%–80%: high-risk citation-laundering network
- >80%–100%: functional citation cartel / structurally closed consensus

These are scored-dimension intensity bands, not estimates of unassessed dimensions. Wording
that implies breadth must also be supported by the distribution of findings across distinct
dimensions. A few severe dimensions do not establish a network-wide pattern.

    ARITHMETIC BAND POSITION: [candidate band from the independent-score rate].
    RISK BAND: [issued band] — computed over [I] independent scored dimensions; breadth
    requirement PASSED.

or:

    RISK BAND: WITHHELD — [coverage, breadth, label-essential, or verification reason].

    MECHANISM LABEL: [label or NONE].

Silence is not withholding. If no risk band is issued, the WITHHELD line is mandatory.

RED FLAGS

Strong evidence of a functionally closed citation network:

- Top 50 papers show >60-70% internal citation density.
- Recent papers continue to heavily cite the same small founding cluster.
- Main review/hub paper is cited more often than original primary evidence.
- Adjacent fields with relevant expertise are cited at very low rates, especially below
  10-15%.
- Contradictory evidence from adjacent fields is ignored or dismissed without engagement.
- Original limitations disappear downstream.
- A weak or narrow finding becomes stronger through repetition.
- The original premise is treated as settled fact rather than a testable hypothesis.
- The decisive test has not been run.
- Failed predictions do not trigger model revision.
- Critics are pathologized or ignored rather than engaged.

-----

GREEN FLAGS

Signs of a healthier field:

- Diverse citation sources beyond a small cluster.
- Regular substantive engagement with adjacent literatures.
- New papers build on fresh evidence rather than recycling the founding cluster.
- Primary empirical tests outnumber reviews/theory papers in load-bearing positions.
- Limitations are preserved downstream.
- Critical papers are cited and engaged.
- Falsification criteria are specified.
- Natural experiments and failed predictions cause model updating.
- Interventions are evaluated against the underlying construct, not only the preferred metric.
