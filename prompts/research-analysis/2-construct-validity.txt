CONSTRUCT-VALIDITY AUDIT PROMPT:

CLAIM VS. MEASUREMENT

-----------------------------------------------------------------
INSTRUMENT PREFLIGHT — MANDATORY FOR FORMAL / LOGGED RUNS   [TOOL-004]
-----------------------------------------------------------------

This prompt is part of the audit instrument. Establish the exact instrument version BEFORE
substantive retrieval, extraction, analysis, or verdict work begins.

A successful fetch indicator, correct repository path, branch label, plausible line count,
matching rendered metadata, or internally self-consistent page does NOT by itself establish
that the intended/current artifact was retrieved. A mutable remote reference can return a
historical representation that is internally self-consistent in every visible field.

PROMPT IDENTITY MARKERS

  - CONSTRUCT-VALIDITY AUDIT PROMPT:
  - CLAIM VS. MEASUREMENT

These markers confirm the prompt family / expected structural features. They do NOT by
themselves establish version currency: an older version may share the same title or markers.

1. RECORD THE INSTRUMENT ACTUALLY IN CONTEXT.

   Record, where available:

   - canonical prompt path or supplied filename;
   - retrieval form: PASTED / ATTACHED / IMMUTABLE REMOTE / MUTABLE REMOTE;
   - requested branch or ref;
   - intended immutable commit/ref, if the run claims a repository version;
   - resolved commit SHA;
   - resolved blob/content hash, or a locally computed cryptographic content hash;
   - exact line count and byte count;
   - prompt identity markers present / absent.

   If a pasted or attached artifact is itself the declared instrument under test, its computed
   content hash may serve as its identity. Do not claim it is the current canonical repository
   version unless that relationship is independently established.

2. MUTABLE-REFERENCE / CURRENCY RULE.

   A path such as /blob/main/, /blob/master/, latest, or another moving branch/ref is a LOCATOR,
   not an immutable version identity.

   Ordinary exploratory work may use a mutable locator with the limitation preserved.

   A FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE run that claims the current repository
   instrument must establish an immutable intended identity independently of the mutable-content
   fetch. Acceptable examples include:

   - an operator-supplied immutable commit permalink;
   - a branch-head / repository-history lookup independent of the content retrieval, followed by
     retrieval of the file at that immutable commit;
   - a second retrieval path that does not reuse the same cache/index, confirmed against an
     immutable commit/blob identity.

   A commit/hash/line-count reported only by the SAME potentially stale rendered representation
   is NOT independent currency evidence.

   If no independent immutable anchor can be established and no explicit collision is observed,
   classify:

     INSTRUMENT VERSION UNVERIFIED

   Such a run may be exploratory but may not count as formal regression or benchmark evidence
   for a claimed canonical version.

3. VERSION-COLLISION ATTRIBUTION GATE.

   If the retrieved representation disagrees with an expected hash, immutable ref, size, line
   count, marker set, or independently established version, classify only:

     VERSION COLLISION — UNRESOLVED

   A failed identity check proves a VERSION MISMATCH. It does NOT establish where the stale
   representation lives. Do NOT conclude from the conflicting retrieval alone:

     REPOSITORY STALE
     RETRIEVAL STALE
     LOCAL COPY STALE
     OPERATOR COPY STALE

   Attribution requires a SECOND, INDEPENDENT discriminator, such as:

   - an immutable commit/blob lookup;
   - repository/file history;
   - a second retrieval path that does not reuse the same cache/index;
   - direct operator confirmation supported by an immutable identity;
   - a locally supplied file whose hash can be compared independently.

   Internal self-consistency is NOT an independent discriminator. A stale representation may
   have a mutually consistent path, branch label, line count, byte size, line gutter, content,
   and rendered repository metadata because all were produced from the same stale snapshot.

4. DISPOSITION.

   FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE RUN:
     - IDENTITY CONFIRMED against the intended immutable instrument -> continue.
     - VERSION COLLISION — UNRESOLVED -> STOP before substantive execution.
     - INSTRUMENT VERSION UNVERIFIED -> exploratory execution may occur, but the run may not be
       logged as evidence for the claimed canonical instrument.

   ORDINARY EXPLORATORY RUN:
     - May continue with INSTRUMENT VERSION UNVERIFIED when no collision is observed.
     - If a collision is observed, do not make claims about repository/instrument state until
       the collision is independently resolved.

5. REQUIRED RUN-HEADER LINE.

   Emit this before the substantive body:

   INSTRUMENT PREFLIGHT: [path/file] @ commit [SHA/UNAVAILABLE] | blob/hash
   [HASH/UNAVAILABLE] | [N] lines | [N] bytes | markers [PRESENT/ABSENT] |
   [IDENTITY CONFIRMED / INSTRUMENT VERSION UNVERIFIED /
   VERSION COLLISION — UNRESOLVED]

   If VERSION COLLISION — UNRESOLVED is returned, also state the conflicting identities and the
   independent discriminator required to resolve them. Do not silently choose one.

GOVERNING RULE:

  A failed identity check proves a version mismatch, not where the mismatch lives.

Purpose:

Use this prompt to audit one paper, study, report, policy document, or institutional claim
before making any broad claim about a field.

Do not evaluate whether the authors are good people.

Do not infer private motive.

Do not summarize the source politely.

Do not defer to prestige, peer review, journal status, citation count, institutional
authority, or the social acceptability of the conclusion.

Your task is narrower:

Compare what the source actually measured to what the source claims, and to what later
citations, institutions, or public arguments use it to prove.

The point is not to decide whether the field is good or bad.

The point is to test whether the measurement supports the claim.

COMPACT VOCABULARY Full rules: shared_primitives.txt

VERIFICATION STATE  -  how thoroughly a source has been checked. This is separate from
evidence type. A peer-reviewed study can be strong in evidence type while remaining weakly
verified.

- LOCATED: source exists and metadata is confirmed; content is unverified.
- ABSTRACT-CONFIRMED: abstract supports relevance; methods and results are not verified.
- FULL-TEXT-CONFIRMED: full text was read and directly supports the specific claim. Do not
  assign this merely because selected excerpts were supplied.
- RECEPTION-CONFIRMED: replies, replications, corrections, retractions, or citation contexts
  were checked against retrieved sources.
- CONTESTED: credible disagreement exists; who is correct remains unresolved.
- REBUTTED: later work directly and substantially challenges the source and the challenge was
  not evidently answered.
- PROVISIONAL: access or retrieval is insufficient, including unverified model memory or
  unresolved source leads.

Rules:

1. Never report a verification state above what was actually checked.
2. Evidence type and verification state are separate axes; report both.
3. FULL-TEXT-CONFIRMED and RECEPTION-CONFIRMED may both apply.
4. Apply the ladder symmetrically to sources supporting and opposing the claim.
5. A PROVISIONAL source may not anchor a MAJOR or FATAL finding.

SOURCE RETRIEVAL-BASIS PREFLIGHT — MANDATORY, UNCONDITIONAL ON VERDICT
  [FAIL-CV-006]
-----------------------------------------------------------------

State this before Section 1, regardless of what the audit concludes:

  SOURCE RETRIEVAL BASIS: [full text fetched from — cite source / abstract only /
  recalled from training data, explicitly flagged as such / mixed — specify which
  sections were retrieved versus recalled]

This declaration is REQUIRED even when the audit produces no findings and returns a clean
acquittal. Rule 6 of the Final Standardized Finding Table — an empty table is a valid output
when nothing of consequence was found — does NOT exempt this line. An empty finding table
with no stated retrieval basis is not a valid output.

For every SPECIFIC load-bearing number quoted anywhere in this audit — dosing, sample size,
effect size, percentages, NNT, or any other figure a reader could independently check — state
its verification state individually, inline or in a compact table:

| Specific figure | Value stated | Verification state | Source |
|---|---|---|---|

A figure recalled from training data and not independently checked against a retrieved source
must be marked PROVISIONAL, even if it turns out to be correct. Being right by recall is not
the same claim as being right by retrieval. This audit must make that distinction inspectable,
not merely produce a correct-looking number.

MULTIPLE SOURCES REPEATING THE SAME FIGURE IS NOT INDEPENDENT VERIFICATION. If several
retrieved documents state the same number, check whether they share a common upstream origin
— for example, multiple database mirrors of the same abstract — before treating agreement as
corroboration. Apparent corroboration from one syndicated source is not stronger evidence
than a single retrieval; it is the same evidence encountered more than once.

This preflight applies with equal force whether the audit is heading toward a DEFEATS finding,
a NARROWS finding, or Verdict A with no findings at all. Retrieval basis is a property of how
the audit was conducted, not of what it concluded.

CONSTRUCT-SIDE RETRIEVAL GATE  [P1; FAIL-CV-003, FAIL-CV-004]

CANONICAL RULE. The compact copies in claim extraction and construct validity,
and every local execution copy, must move together.

Every construct-side check prosecutes specifics that can be supplied from
memory - what a scale contains, whether a property is established, whether a
belief is accurate. Do not. Rate each on retrieved source material only.

CANONICAL CONSTRUCT PROPERTIES

Use these five property names everywhere:

  PREVALENCE
  FORM
  DOMAIN
  WRONGNESS
  HARM

Construct-property status:

  ESTABLISHED-REPORTED
    The paper measures or reports the property in fetched text.

  ESTABLISHED-CITED
    The property is established in cited prior work that you actually checked.

  ASSERTED
    You fetched where establishment would appear - the introduction and relevant
    citations - and establishment is absent.

  UNKNOWN
    You did not fetch where establishment would appear, such as an abstract-only
    or snippet-only run.

MAP / PROSECUTOR DIVISION

The claim map deliberately hands off ESTABLISHED-CITED as a coarse retrieval
status. The construct prosecutor must then classify whether the cited support is
contested or uncontested in the respect the paper requires. Do not duplicate that
judgment into the map.

Operationalization retrieval basis:

  ITEMS-RETRIEVED
    The actual items, coding rules, or inclusion criteria were fetched and read.

  ITEMS-INFERRED
    The assessment is based on the scale's name, family, or a related scale.

ITEMS-* values state RETRIEVAL BASIS. They are not competing scope outcomes.

Operationalization scope result:

  coextensive
  narrower
  broader
  UNKNOWN

ITEMS-RETRIEVED permits coextensive / narrower / broader classification.
ITEMS-INFERRED requires the resulting scope status UNKNOWN.

HARD RULE

A construct-side finding may be load-bearing, MAJOR, or FATAL only when it rests
on ESTABLISHED-REPORTED, ESTABLISHED-CITED, ASSERTED, or ITEMS-RETRIEVED.

Anything resting on UNKNOWN or ITEMS-INFERRED receives finding disposition
PROVISIONAL, may not be load-bearing, and may not be rated MAJOR or FATAL.

State the retrieval basis for every construct-side finding.

GRADE-BEFORE-ASSERT  [P2; GUARD-006]

CANONICAL RULE. The compact copies in claim extraction and construct validity,
and every local execution copy, must move together.

Before rating a belief "wrong," or rating an accurate version as pathologized,
grade the SPECIFIC belief using this closed vocabulary:

  ESTABLISHED-FALSE
  GRADE-CONTESTED
  FRINGE
  ESTABLISHED-ACCURATE

A wrongness finding - the paper under-grades its target - fires at strength only
where a named sub-claim is ESTABLISHED-FALSE.

A pathologization finding - the scale penalizes an accurate version - fires at
strength only where the penalized version is ESTABLISHED-ACCURATE.

P2 is a STRENGTH GATE, not a severity vocabulary:

  STRONG
    The relevant pole is established: ESTABLISHED-FALSE for a wrongness finding,
    or ESTABLISHED-ACCURATE for a pathologization finding.

  WEAK
    The specific belief is GRADE-CONTESTED or FRINGE. Severity is capped MINOR
    and the finding may not anchor the verdict.

  VOID
    No specific sub-claim was graded, or retrieval is insufficient to place it
    on the spectrum. Severity is NONE and the finding is dropped.

Apply this symmetrically. Do not assert that the paper's target is settled-wrong,
and do not assert that a penalized belief is settled-accurate, without the
required grade. "The construct is contested" alone is not a finding.

FAILURE LOCATION  -  where the failure actually lives:

- PAPER: the source itself overclaims or uses an invalid proxy.
- CITATION: the source is defensible but later literature inflates it.
- PR / MEDIA: a press release or coverage strips caveats or broadens the claim.
- MODEL / RETRIEVAL: summarizers or search systems reproduce the inflated version.
- MIXED: more than one layer contributes; specify which layer contributes what.

Attacking a defensible paper for its press release is a category error. Classify the
responsible layer honestly.

AUDIT INSTRUCTIONS

You are auditing construct validity.

Do not begin by balancing the source with generic praise.

Do not add reassurance clauses unless they are doing real evidentiary work.

Do not use phrases like "it is important to acknowledge" or "this does not invalidate" unless
the qualification is necessary to prevent factual overstatement.

Do not soften "invalid proxy" into "limited proxy" if the measurement cannot support the
claim.

Do not treat peer review, citation count, or institutional adoption as evidence that the
construct was measured correctly.

Answer the following sections.

For each property the claim map marked ASSERTED, state whether the paper's

2. RETRIEVAL CAP

Apply [P1]. A property marked UNKNOWN receives finding disposition PROVISIONAL
and may not be load-bearing. State this section's retrieval depth exactly:

  "assessed from [abstract / full text / introduction plus citations checked]."

Abstract-only means construct properties default UNKNOWN. That produces a
PROVISIONAL gap, not a confirmed absence.

3. ESTABLISHED-CITED PROSECUTOR SPLIT

The claim-map handoff is deliberately coarse. For every ESTABLISHED-CITED
property, the construct prosecutor must classify it as:

- uncontested in the respect the paper requires; or
- contested in the respect the paper requires.

A citation licenses the bounded finding it reports, not every causal or normative
load placed on it. If the paper uses a real citation to underwrite a stronger
claim than the citation supports, name:

- the specific citation;
- the bounded result it supports;
- the exact stronger load placed on it.

Example: "belief X correlates with prejudice measure Y" does not by itself
license "reducing X's scale reduces racism."

"The field is insulated" is not a finding.

4. NOT-FIRING CONDITION - MANDATORY

If the relevant properties are ESTABLISHED-REPORTED or ESTABLISHED-CITED and
uncontested in the respect the paper requires, write:

  "construct adequately established"

and raise no construct-establishment finding.

5. CONCEDE TEST

  "The intervention reduced scores on a construct whose [named properties] the
  paper does not establish."

5. CONFOUND AUDIT

Identify obvious confounds.

Ask:

- What variables could explain the measured outcome besides the proposed explanation?
- What confounds would a practitioner, clinician, performer, or domain expert immediately
  notice?
- Did the authors control for these confounds?
- Did the authors acknowledge them?
- Did later citations forget the confounds?
- Would the omitted confounds change the interpretation?

Classify each confound:

Confound | Domain obvious? | Controlled? | Acknowledged? | Impact if omitted

Impact options:

- Low
- Moderate
- High
- Fatal for the strong claim

6. ECOLOGICAL VALIDITY CHECK

Ask:

- Does the task resemble the real-world phenomenon being explained?
- Does the sample resemble the population the claim is applied to?
- Does the time scale match the real process?
- Does the measured behavior occur under realistic pressure, incentives, constraints, or
  selection?
- Is the study measuring performance, stated belief, compliance, perception, or institutional
  output?
- Are those being conflated?

Verdict:

- High ecological validity
- Moderate ecological validity
- Low ecological validity
- Ecologically valid only for a narrower claim
- Not ecologically valid for the claim being made

7. DECISIVE-TEST CHECK

What test would directly measure the claimed construct?

Answer:

- What would the decisive test measure?
- What population would it study?
- What controls would be required?
- What outcome would support the source's claim?
- What outcome would weaken or falsify the source's claim?
- Does the current source run that test?
- If not, does the field acknowledge that the decisive test has not been run?

Then state:

"The decisive test would be: [ONE-SENTENCE TEST SPECIFICATION]."

8. CROSS-REANALYSIS OBJECT CHECK

If two or more independent reanalyses, replications, or critiques reach different conclusions
about the source, before treating them as agreeing or conflicting, check what each one
actually tested.

Ask:

- Did each reanalysis test the same object  -  the full result, a single component, a specific
  subgroup, a specific time window?
- Or did they test different objects that only sound like the same dispute?
- Is apparent disagreement actually a scope mismatch rather than a genuine unresolved
  question?
- Is apparent convergence masking that the harder or more specific version of the question was
  never independently re-tested?

State plainly: for each pair of reanalyses in tension, are they actually contradicting each
other, or talking past each other?

Do not report a dispute as "resolved" or "settled" if the reanalyses that appear to resolve it
tested a narrower or different claim than the one in question. Do not report a dispute as
"ongoing" if it is actually two non-competing findings about different objects.

- Are they citing an inflated version of the finding?
- Are they using the source as evidence, or as a premise?

13. THE CONCEDE TEST

Run this on every proposed finding before rating severity or choosing the verdict.

For each finding, ask:

IF THIS FINDING WERE FULLY CONCEDED  -  granted entirely, with no argument  -  WOULD THE CLAIM
UNDER AUDIT STILL STAND?

- SURVIVES: the claim still holds. This is a limitation, not a defeater. Report it, but it may
  not be rated MAJOR or FATAL and may not anchor the verdict.
- NARROWS: the claim survives only in smaller scope, such as a different population, weaker
  effect, or narrower conditions. State the surviving claim explicitly.
- DEFEATS: the audited claim does not follow. This is load-bearing.

Create a table:

| Finding | Concede test: SURVIVES / NARROWS / DEFEATS | Surviving claim if NARROWS |
|---|---|---|

This test separates limitations from claim-defeating failures without softening either.

It cuts both ways:

- A DEFEATS result strengthens a finding by showing it is load-bearing.
- A SURVIVES result shows that the finding cannot carry the verdict.
- Do not turn a raw count of overlapping limitations into a claim-defeating verdict.
  Consolidate duplicated findings and judge what scope the claim actually retains.

SCOPE-LOSS ASSESSMENT  -  REQUIRED FOR EVERY NARROWS RESULT

Do not map verdicts by counting NARROWS findings. State how much of the audited claim survives
after the finding is conceded:

- INCIDENTAL NARROWING: wording, boundary conditions, or precision changes, but the claim
  remains substantially the same in population, construct, direction, and practical use. This
  ordinarily supports verdict B, not C.
- MATERIAL NARROWING: the claim survives only for a meaningfully smaller population, weaker
  construct, shorter time horizon, reduced effect, or more limited application. The strong
  claim is invalid, but a useful narrower claim remains. This supports verdict C.
- NEAR-DEFEAT NARROWING: only a trivial, tautological, or practically different remainder
  survives. Do not use NARROWS to avoid DEFEATS. Reclassify as DEFEATS if the surviving
  proposition no longer does the work for which the audited claim is being used.

For each NARROWS result, add:

| Finding | Scope-loss level | Original claim | Surviving claim | What practical or inferential work is lost? |
|---|---|---|---|---|

VERDICT MAPPING:

- No DEFEATS and no MATERIAL NARROWING: use A or B according to the remaining limitations and
  evidentiary strength.
- One or more MATERIAL NARROWING findings and no DEFEATS: use C.
- One or more DEFEATS: use D, E, or F according to the mechanism, severity, and failure
  location.
- If evidence is insufficient to run the test reliably: use G.

The decisive question is not how many findings narrow the claim. It is whether the surviving
claim remains substantially the claim named in map field 6 and can still support the use under
audit.

Do not use the concede test to cut findings merely because they are limitations. Report them,
but enforce the severity cap.

14. VERDICT

Do not return one letter when any finding is DEFEATS. Output a split claim-space object:

- Claim under audit: VALID / USEFUL-FOR-NARROWER / INVALID
- DEFEATS finding(s), if any:
- Failure mechanism: none / major proxy failure / fatal construct-validity failure /
  citation-laundered premise / insufficient information
- Surviving residual: [the exact narrowed claim left standing] OR "none"
- Residual usefulness grade: A / B / C / G / none

Residual usefulness grades:

A. Valid evidence for the residual claim. B. Partial evidence with clear limits. C. Useful for
the stated narrower residual, invalid for the stronger claim. G. Insufficient information to
judge.

"None" is a REQUIRED, reachable output. A DEFEATS finding does not guarantee a usable
residual. A proxy can fail so completely that nothing underneath is useful. Do not manufacture
a comforting residual.

Derive the object from the Concede Test rather than from the number or rhetorical force of
findings. Explain it in 3-6 sentences.

Worked example:

- Claim under audit: INVALID - "reduces unscientific genetic essentialism and thereby racism."
- DEFEATS finding: the proxy move from scale scores to racism.
- Failure mechanism: fatal construct-validity failure for the strong claim.
- Surviving residual: "The curriculum can lower scores on the authors' essentialism-related
  scales relative to Mendelian instruction in these student samples."
- Residual usefulness grade: C.

Do not hedge unless the evidence requires it. If the residual is none, say none. If confidence
or dispute-resolution language differs from an earlier section, resolve the discrepancy here
and state which characterization is correct.

AXIS DEFINITIONS

Verification state describes how thoroughly the evidence item was retrieved and
checked.

Finding disposition describes the row's current adjudicative state:

  CONFIRMED
    The retrieved evidence and the audit's stated reasoning support the finding
    as written.

  CONTESTED
    The finding is supported but credible contrary evidence or interpretation
    remains unresolved.

  PROVISIONAL
    Retrieval or source-chain work is incomplete. The finding may not be
    load-bearing or rated MAJOR or FATAL.

These axes may differ. For example, a source can be FULL-TEXT-CONFIRMED while
the finding drawn from it remains CONTESTED.

RULES

1. A finding missing either mandatory falsifiability field is not inspectable and may not be
   rated MAJOR or FATAL.
2. Severity must agree with verification state, construct-side retrieval
   fields, P2 strength, and finding disposition. A PROVISIONAL finding cannot be
   MAJOR or FATAL. A P2-WEAK finding may not exceed MINOR. A P2-VOID finding has
   severity NONE and is dropped.
3. A SURVIVES finding cannot be MAJOR or FATAL and may not anchor the verdict.
4. A NARROWS finding must state the surviving claim and scope-loss level. A merely incidental
   narrowing does not by itself require verdict C.
5. Target claim must match field 6 of the shared Claim Map. Use MAP GAP rather than silently
   substituting another claim.
6. If no findings of consequence were produced, say so plainly and submit an empty table with
   a one-line statement. A prosecutor that never returns "nothing of consequence here" is not
   measuring anything. THIS DOES NOT WAIVE the Source Retrieval-Basis Preflight above — an
   empty table still requires a stated retrieval basis and, where specific figures were relied
   upon in reaching the acquittal, their individual verification states.
