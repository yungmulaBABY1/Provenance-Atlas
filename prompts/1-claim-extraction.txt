CLAIM EXTRACTION / INFLATION MAP
================================

Shared pre-stage. Runs AFTER target selection, BEFORE the prosecutors.

-----------------------------------------------------------------
INSTRUMENT PREFLIGHT — MANDATORY FOR FORMAL / LOGGED RUNS   [TOOL-004]
-----------------------------------------------------------------

This prompt is part of the audit instrument. Establish the exact instrument version BEFORE
substantive retrieval, extraction, analysis, or verdict work begins.

A successful fetch indicator, correct repository path, branch label, plausible line count,
matching rendered metadata, or internally self-consistent page does NOT by itself establish
that the intended/current artifact was retrieved. A mutable remote reference can return a
historical representation that is internally self-consistent in every visible field.

PROMPT IDENTITY MARKERS

  - CLAIM EXTRACTION / INFLATION MAP

These markers confirm the prompt family / expected structural features. They do NOT by
themselves establish version currency: an older version may share the same title or markers.

1. RECORD THE INSTRUMENT ACTUALLY IN CONTEXT.

   Record, where available:

   - canonical prompt path or supplied filename;
   - retrieval form: PASTED / ATTACHED / IMMUTABLE REMOTE / MUTABLE REMOTE;
   - requested branch or ref;
   - intended immutable commit/ref, if the run claims a repository version;
   - resolved commit SHA;
   - resolved blob/content hash, or a locally computed cryptographic content hash;
   - exact line count and byte count;
   - prompt identity markers present / absent.

   If a pasted or attached artifact is itself the declared instrument under test, its computed
   content hash may serve as its identity. Do not claim it is the current canonical repository
   version unless that relationship is independently established.

2. MUTABLE-REFERENCE / CURRENCY RULE.

   A path such as /blob/main/, /blob/master/, latest, or another moving branch/ref is a LOCATOR,
   not an immutable version identity.

   Ordinary exploratory work may use a mutable locator with the limitation preserved.

   A FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE run that claims the current repository
   instrument must establish an immutable intended identity independently of the mutable-content
   fetch. Acceptable examples include:

   - an operator-supplied immutable commit permalink;
   - a branch-head / repository-history lookup independent of the content retrieval, followed by
     retrieval of the file at that immutable commit;
   - a second retrieval path that does not reuse the same cache/index, confirmed against an
     immutable commit/blob identity.

   A commit/hash/line-count reported only by the SAME potentially stale rendered representation
   is NOT independent currency evidence.

   If no independent immutable anchor can be established and no explicit collision is observed,
   classify:

     INSTRUMENT VERSION UNVERIFIED

   Such a run may be exploratory but may not count as formal regression or benchmark evidence
   for a claimed canonical version.

3. VERSION-COLLISION ATTRIBUTION GATE.

   If the retrieved representation disagrees with an expected hash, immutable ref, size, line
   count, marker set, or independently established version, classify only:

     VERSION COLLISION — UNRESOLVED

   A failed identity check proves a VERSION MISMATCH. It does NOT establish where the stale
   representation lives. Do NOT conclude from the conflicting retrieval alone:

     REPOSITORY STALE
     RETRIEVAL STALE
     LOCAL COPY STALE
     OPERATOR COPY STALE

   Attribution requires a SECOND, INDEPENDENT discriminator, such as:

   - an immutable commit/blob lookup;
   - repository/file history;
   - a second retrieval path that does not reuse the same cache/index;
   - direct operator confirmation supported by an immutable identity;
   - a locally supplied file whose hash can be compared independently.

   Internal self-consistency is NOT an independent discriminator. A stale representation may
   have a mutually consistent path, branch label, line count, byte size, line gutter, content,
   and rendered repository metadata because all were produced from the same stale snapshot.

4. DISPOSITION.

   FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE RUN:
     - IDENTITY CONFIRMED against the intended immutable instrument -> continue.
     - VERSION COLLISION — UNRESOLVED -> STOP before substantive execution.
     - INSTRUMENT VERSION UNVERIFIED -> exploratory execution may occur, but the run may not be
       logged as evidence for the claimed canonical instrument.

   ORDINARY EXPLORATORY RUN:
     - May continue with INSTRUMENT VERSION UNVERIFIED when no collision is observed.
     - If a collision is observed, do not make claims about repository/instrument state until
       the collision is independently resolved.

5. REQUIRED RUN-HEADER LINE.

   Emit this before the substantive body:

   INSTRUMENT PREFLIGHT: [path/file] @ commit [SHA/UNAVAILABLE] | blob/hash
   [HASH/UNAVAILABLE] | [N] lines | [N] bytes | markers [PRESENT/ABSENT] |
   [IDENTITY CONFIRMED / INSTRUMENT VERSION UNVERIFIED /
   VERSION COLLISION — UNRESOLVED]

   If VERSION COLLISION — UNRESOLVED is returned, also state the conflicting identities and the
   independent discriminator required to resolve them. Do not silently choose one.

GOVERNING RULE:

  A failed identity check proves a version mismatch, not where the mismatch lives.

-----------------------------------------------------------------
WHY THIS STAGE EXISTS
-----------------------------------------------------------------

Three prosecutors are about to audit this target. Without a shared claim map, they will audit
three different claims: construct validity attacks the paper's own operationalization,
internal validity attacks the study design, and citation network attacks the downstream
restatement. The resulting critique reads as incoherent because each stage was aiming at a
different object.

This stage produces the single claim map all three receive. It also does the thing that most
often separates a challenge that lands from one that gets waved off: it locates WHERE the
inflation begins, so the critique attacks the layer actually responsible rather than the
easiest target.

This stage does NOT evaluate whether the claim is true. It extracts and maps. Judgment belongs
to the prosecutors and the human. Resist the pull to start critiquing here. A map contaminated
by a verdict is worse than no map because every downstream stage inherits the verdict as a
premise.

COMPACT VOCABULARY
-----------------------------------------------------------------

This is the operational copy. shared-primitives.txt records the full rationale and
synchronization history; it is not loaded automatically.

VERIFICATION STATE  -  how thoroughly a source has been checked. This is separate from
evidence type and from the Field 4 provenance states SUPPLIED / RETRIEVED / RECALLED / NONE
FOUND.

- LOCATED: source exists and metadata is confirmed; content is unverified.
- ABSTRACT-CONFIRMED: abstract supports relevance; methods and results are not verified.
- FULL-TEXT-CONFIRMED: full text was read and directly supports the specific claim.
- RECEPTION-CONFIRMED: replies, replications, corrections, retractions, citation graphs, or
  citation contexts were checked against retrieved sources.
- CONTESTED: credible disagreement exists; who is correct remains unresolved.
- REBUTTED: later work directly and substantially challenges the source and the challenge was
  not evidently answered.
- PROVISIONAL: access or retrieval is insufficient, including unverified model memory or
  unresolved source leads.

- CROSS-SOURCE-CONFIRMED: an ATTRIBUTION relationship was checked by reading BOTH the
  downstream text and the audited source  -  plus a successor or alternative source where one
  is implicated  -  and comparing what is claimed against what each actually supports. This is
  a distinct verification act: not reception checking (how a source fared) and not full-text
  checking (what one source says), but whether a downstream text has assigned a claim to a
  source that supports it. Use for every MISATTRIBUTED or ATTRIBUTED ELSEWHERE classification
  you actually verified.

DO NOT INVENT VERIFICATION STATES. The list above is the whole vocabulary. Live runs have
produced "ESTABLISHED FROM SOURCE," "RECONSTRUCTION FROM SOURCE," and similar ad-hoc labels.
Each reads as authoritative, none is defined anywhere, and a downstream stage cannot tell what
was actually checked. If no state fits what you did, describe it in a sentence rather than
coining a label  -  an undefined state is worse than plain prose.

For a field that is an author reconstruction rather than a retrieval, write "author
reconstruction from [source field]." That is a description, not a verification state.

Rules:

1. Never report a verification state above what was actually checked.
2. Evidence type and verification state are separate axes; report both.
3. FULL-TEXT-CONFIRMED, RECEPTION-CONFIRMED, and CROSS-SOURCE-CONFIRMED answer different
   questions and may coexist where each was actually established.
4. Field 4 provenance states describe how a downstream item entered the map; verification
   states describe what was checked. Do not substitute one axis for the other.

CONSTRUCT-SIDE RETRIEVAL GATE  [P1; FAIL-CV-003, FAIL-CV-004]

CANONICAL RULE. The compact copies in claim extraction and construct validity,
and every local execution copy, must move together.

Every construct-side check prosecutes specifics that can be supplied from
memory - what a scale contains, whether a property is established, whether a
belief is accurate. Do not. Rate each on retrieved source material only.

CANONICAL CONSTRUCT PROPERTIES

Use these five property names everywhere:

  PREVALENCE
  FORM
  DOMAIN
  WRONGNESS
  HARM

Construct-property status:

  ESTABLISHED-REPORTED
    The paper measures or reports the property in fetched text.

  ESTABLISHED-CITED
    The property is established in cited prior work that you actually checked.

  ASSERTED
    You fetched where establishment would appear - the introduction and relevant
    citations - and establishment is absent.

  UNKNOWN
    You did not fetch where establishment would appear, such as an abstract-only
    or snippet-only run.

MAP / PROSECUTOR DIVISION

The claim map deliberately hands off ESTABLISHED-CITED as a coarse retrieval
status. The construct prosecutor must then classify whether the cited support is
contested or uncontested in the respect the paper requires. Do not duplicate that
judgment into the map.

Operationalization retrieval basis:

  ITEMS-RETRIEVED
    The actual items, coding rules, or inclusion criteria were fetched and read.

  ITEMS-INFERRED
    The assessment is based on the scale's name, family, or a related scale.

ITEMS-* values state RETRIEVAL BASIS. They are not competing scope outcomes.

Operationalization scope result:

  coextensive
  narrower
  broader
  UNKNOWN

ITEMS-RETRIEVED permits coextensive / narrower / broader classification.
ITEMS-INFERRED requires the resulting scope status UNKNOWN.

HARD RULE

A construct-side finding may be load-bearing, MAJOR, or FATAL only when it rests
on ESTABLISHED-REPORTED, ESTABLISHED-CITED, ASSERTED, or ITEMS-RETRIEVED.

Anything resting on UNKNOWN or ITEMS-INFERRED receives finding disposition
PROVISIONAL, may not be load-bearing, and may not be rated MAJOR or FATAL.

State the retrieval basis for every construct-side finding.

GRADE-BEFORE-ASSERT  [P2; GUARD-006]

CANONICAL RULE. The compact copies in claim extraction and construct validity,
and every local execution copy, must move together.

Before rating a belief "wrong," or rating an accurate version as pathologized,
grade the SPECIFIC belief using this closed vocabulary:

  ESTABLISHED-FALSE
  GRADE-CONTESTED
  FRINGE
  ESTABLISHED-ACCURATE

A wrongness finding - the paper under-grades its target - fires at strength only
where a named sub-claim is ESTABLISHED-FALSE.

A pathologization finding - the scale penalizes an accurate version - fires at
strength only where the penalized version is ESTABLISHED-ACCURATE.

P2 is a STRENGTH GATE, not a severity vocabulary:

  STRONG
    The relevant pole is established: ESTABLISHED-FALSE for a wrongness finding,
    or ESTABLISHED-ACCURATE for a pathologization finding.

  WEAK
    The specific belief is GRADE-CONTESTED or FRINGE. Severity is capped MINOR
    and the finding may not anchor the verdict.

  VOID
    No specific sub-claim was graded, or retrieval is insufficient to place it
    on the spectrum. Severity is NONE and the finding is dropped.

Apply this symmetrically. Do not assert that the paper's target is settled-wrong,
and do not assert that a penalized belief is settled-accurate, without the
required grade. "The construct is contested" alone is not a finding.

OUTPUT  -  THE CLAIM MAP (SIX FIELDS)
-----------------------------------------------------------------

1. WHAT WAS LITERALLY MEASURED

The actual operationalization. Instrument, data source, population, sample, time period, and
unit of analysis. Be concrete and specific: not "gaming performance," but "character
advancement rate in two MMOs, 2006-2008, among registered players, controlling for hours
played."

For non-academic targets: what is the underlying data or observation? A policy document's
"outcome" is often an administrative metric; a news article's "study shows" points to a
specific measurement. Name it.

If the source does not clearly state what was measured, say so. That is itself a finding, and
it belongs in the map.

DEFINITION-OPERATIONALIZATION CHECK  [FAIL-CV-001, FAIL-CV-004]

Mandatory when a central construct is named. Extract:

- the source's explicit definition, quoted;
- the actual items, coding rules, or inclusion criteria used to measure it.

Apply [P1]. Record both:

- Operationalization retrieval basis:
  ITEMS-RETRIEVED / ITEMS-INFERRED
- Operationalization scope result:
  coextensive / narrower / broader / UNKNOWN

CANONICAL VOCABULARY - local execution copy must match [P1].

If ITEMS-INFERRED, the scope result is UNKNOWN. Record the definition, note that
the items were not retrieved, and DO NOT classify the measure coextensive,
narrower, or broader.

Inferring a scale's contents from its name, family, or a related scale is barred
because it manufactures false scope creep.

If ITEMS-RETRIEVED, classify the operationalization as:

- coextensive;
- narrower; or
- broader.

If broader, list the specific out-of-scope items and record:

  Definition-operationalization mismatch
  Subtype: definitional scope creep

MAP CONTENT, not a verdict.

CONSTRUCT-ESTABLISHMENT CHECK  [FAIL-CV-002, FAIL-CV-003]

Mandatory only when the source escalates from a narrow efficacy claim to a
NORMATIVE or CAUSAL claim about the construct, such as "this belief is harmful"
or "reducing it reduces X." A paper claiming only "we moved scores on our scale
in these samples" does not trigger this check.

When triggered, record each canonical property with a construct-property status
from [P1]:

- PREVALENCE:
  held at non-trivial rates in the target population?
- FORM:
  coherent strong endorsement or weak, scattered endorsement?
- DOMAIN:
  which traits or contexts; absolute or partial contribution?
- WRONGNESS:
  which specific sub-claims are false, accurate, contested, or fringe, and to
  what degree? Apply [P2].
- HARM:
  does holding the construct produce the claimed harm?

Write ASSERTED only if you fetched the introduction and relevant citations and
found establishment absent. Otherwise write UNKNOWN.

HARM for a well-studied construct is often established by reference and
invisible in an abstract; never write ASSERTED without checking the cited
literature.

The map records ESTABLISHED-CITED coarsely. Whether that citation is contested
or uncontested in the respect the paper requires is deliberately left to the
construct prosecutor.

MAP CONTENT, not a verdict.

PUBLICATION STATUS:

Does a corrigendum, correction, retraction, or expression of concern exist for this source?

  [yes  -  cite it / no / not checked]

Factual publication record only. Do NOT list critiques, replies, or reception here. That
belongs in the counter-audit's reception gate. Listing it upstream primes the prosecutors
toward the source's controversy rather than its text.

2. STRONGEST CLAIM THE SOURCE ITSELF MAKES

Quote or closely paraphrase the source's own strongest assertion, PRESERVING ITS OWN HEDGING.
If it says "suggests," keep "suggests." If it says "likely," keep "likely." Note where this
claim appears - abstract, conclusion, press quote - since abstracts routinely overstate the
body.

Sources frequently hedge properly in the methods and overstate in the abstract. Capture both
if they differ.

3. WEAKER DEFENSIBLE CLAIM THE EVIDENCE ACTUALLY SUPPORTS

The narrower statement the measurement can carry. This is a reconstruction, not a quotation.
State what the data would support with appropriate scope limits: population sampled,
conditions tested, effect size, and level of analysis.

ITEM TRACKING  [FAIL-CV-001]

When a definition-operationalization mismatch exists AND the items are ITEMS-RETRIEVED, this
field must track the ACTUAL ITEMS rather than the stated definition.

If the items are ITEMS-INFERRED, track the stated definition and write that the item-level
defensible claim is UNKNOWN pending item retrieval.

This field is the reference point for the entire audit. The gap between #2 and #3 is the
paper-level overclaim; the gap between #3 and #4 is the downstream inflation. Both matter, and
they are different problems with different remedies.

4. BROADER CLAIM ATTACHED DOWNSTREAM

What later citations, assessment reports, press releases, media, policy, or model summaries
assert on the basis of this source. Quote where possible.

Label each downstream restatement with its layer (see primitives Section 3):

- citing literature
- PR / media
- policy
- model / retrieval

THIS FIELD IS ACTIVE, NOT PASSIVE.

Do not wait for downstream material to be supplied. A user pasting a paper will not have the
assessment report, the press release, or the coverage. Finding out whether the claim was
inflated is part of the job, not a precondition for doing it.

IF YOU HAVE RETRIEVAL:

Search for downstream restatements before writing this field. Look for the source cited in
later literature, assessment or synthesis reports, institutional press releases, news
coverage, and encyclopedia or summary entries. Quote what you find.

FOUR PROVENANCE STATES  -  label every downstream item with exactly one:

  SUPPLIED The user provided the text. Quote it.

  RETRIEVED You searched and found the actual downstream text. Quote it and name where it came
  from.

  RECALLED You believe downstream inflation occurred but did NOT retrieve the text. State this
  plainly as its own labeled line, NOT as a parenthetical or footnote. It may not be quoted as
  though verified and may not anchor Field 5's failure-location classification.

  NONE FOUND You searched and found nothing. Say which searches you ran.

THE PARENTHETICAL FAILURE  -  observed in a live run and explicitly forbidden.

A run declared "no downstream uses supplied, fields 5-6 PROVISIONAL," then added a
parenthetical noting the paper was "later widely restated in secondary literature and
assessment reports" - unretrieved, unquoted, offered "for completeness of the map only."

That is RECALLED material wearing the costume of a footnote. It neither retrieves nor cleanly
abstains, and it lets unverified knowledge into the map through a side door where downstream
stages will read it as context.

If you know something about downstream use, label it RECALLED on its own line. Do not append
it as an aside.

IF NOTHING IS RETRIEVABLE:

Write "no downstream uses retrieved  -  inflation analysis limited to the source itself," and
state whether that reflects an absence of downstream use or an absence of retrieval
capability.

Those are different findings, and the distinction matters:

- the first is evidence the claim did not travel;
- the second is evidence you could not check.

WHICH FIELDS GO PROVISIONAL  -  field-specific, not blanket:

  FIELD 4  -  PROVISIONAL You cannot distinguish "no downstream use exists" from "I could not
  retrieve it."

  FIELD 5  -  PARTIALLY PROVISIONAL Mark the DOWNSTREAM component provisional. The
  WITHIN-SOURCE component - prominence asymmetry between abstract and methods, or a headline
  stated at higher confidence than the results section supports - is established from the
  paper alone and is NOT provisional.

    State both parts separately rather than marking the whole field.

  FIELD 6  -  CONDITIONAL If Field 6 targets the source's own claim, it needs no downstream
  material and is NOT provisional.

    If Field 6 targets a downstream restatement, it is provisional, and you should reconsider
    whether that is the right target given that you could not retrieve the restatement.

Do not mark fields provisional in a block. A blanket PROVISIONAL on a field with a verifiable
component discards work you actually did.

DO NOT RECONSTRUCT DOWNSTREAM CLAIMS FROM MEMORY AND PRESENT THEM AS FOUND.

A fabricated inflation chain corrupts every stage that follows. It is the single most damaging
error available at this stage: downstream prosecutors will audit a laundering pathway that may
not exist.

ATTRIBUTION CHECK  -  RUN ON EVERY DOWNSTREAM ITEM BEFORE RECORDING IT.

A downstream restatement belongs in this map only if THE AUDITED SOURCE actually supports it.
Before recording an item, ask:

  Could the audited source, on its own, support this restatement?

If NO - if the restatement requires a successor paper, a later extension, a larger dataset, a
pooled or multi-study analysis, or a different source entirely - DO NOT STOP THERE.

Ask the second question:

  WHO DOES THE DOWNSTREAM TEXT CITE FOR IT?

Two facts can be true at once: the claim rests on another source, AND the downstream text
attributes it to the audited source.

The second is laundering, and it is the mechanism by which a paper acquires claims it never
made.

  CITES THE ACTUAL SUPPORTING SOURCE ATTRIBUTED ELSEWHERE  -  [restatement] rests on [actual
  source], and the downstream text cites it correctly. Not inflation by the audited source.

  CITES THE AUDITED SOURCE MISATTRIBUTED  -  [downstream text] attributes [restatement] to the
  audited source, which does not support it.

    THIS IS INFLATION, and it is the strongest form: the citation confers authority the source
    does not have.

    Quote the citing sentence WITH its citation.

    Failure location: CITATION.

  CITES THE AUDITED SOURCE JOINTLY WITH THE ACTUAL SOURCE Do not classify from the sentence
  alone. Run the document-level joint-citation check below.

JOINT CITATION REQUIRES A DOCUMENT-LEVEL CHECK BEFORE CLASSIFICATION.

A joint citation - "(Source A, Source B)" - is ambiguous on its own. Before classifying it,
search the citing document for whether it distinguishes the sources' scopes ANYWHERE, not only
in the sentence at issue.

  THE DOCUMENT DISTINGUISHES THEM ELSEWHERE It names what each source covers, dates them
  separately, or describes one as extending the other.

    SYNTHESIS ATTRIBUTION, not misattribution.

    The joint citation is shorthand for a research program in a document that has already told
    the reader which source supplies what.

    Record it, note the distinction, and do not classify it as inflation.

  THE DOCUMENT NEVER DISTINGUISHES THEM MISATTRIBUTED.

    A reader has no way to learn that the audited source does not support the claim, and the
    joint citation confers authority it lacks.

OBSERVED FAILURE THIS CLOSES:

A run classified an assessment report's joint citation as MISATTRIBUTED on the sentence alone.

A later run retrieved the same report's earlier chapter, found that it explicitly stated the
1998 study covered 600 years and the 1999 study extended to 1,000 years, and correctly
reclassified the joint citation as SYNTHESIS ATTRIBUTION.

The sentence-level rule produced a false positive against a careful document.

THIS ASYMMETRY IS DELIBERATE.

A single-source misattribution is established at sentence level. A joint citation is not. It
requires showing that the document does not disambiguate.

That is a higher bar, and it should be.

MISATTRIBUTED IS NOT A WEAKER FINDING THAN ORDINARY INFLATION.

It is a stronger one. Ordinary inflation stretches what a source said; misattribution assigns
it something it never said, under its name.

Do not let the fact that another source could support the claim become a reason to clear the
citing text. That is the loophole, and it exonerates exactly the behavior this stage exists to
detect.

OBSERVED FAILURE THIS CLOSES:

Two maps of the same paper reached opposite conclusions on the same restatement.

One reasoned that the millennial claim rests on a successor paper, recorded ATTRIBUTED
ELSEWHERE, and found no inflation.

The other retrieved the assessment report's actual sentence and found the millennial claim
asserted with the AUDITED paper cited for it.

The second was correct. The first applied the attribution check faithfully and arrived at the
wrong answer because the rule stopped at the first question.

RETRIEVE THE CITING SENTENCE, NOT THE CLAIM.

You cannot run this check on a remembered summary of what downstream sources say. "The field
commonly states X" tells you nothing about who is cited for X.

Get the sentence and its citation, or mark the item RECALLED and do not classify it.

THE TEST IS SCOPE ARITHMETIC.

Compare what the restatement asserts against what the source measured. If the downstream claim
covers a longer period, a broader population, a different outcome, a larger geography, or a
finer resolution than the source's design reaches, something other than this source is
carrying it. Find out what.

SAME-AUTHOR SUCCESSORS ARE STILL DIFFERENT SOURCES.

A follow-on paper by the same team, extending the same method to new data, is new work with
its own methods and its own uncertainty statements.

Treating its claims as inflation of the earlier paper is a category error unless the
downstream text itself cites the earlier paper for the successor's claim.

If the earlier paper is cited alone, classify the item as MISATTRIBUTED. If it is cited
jointly with the successor, apply the document-level joint-citation check before deciding
between SYNTHESIS ATTRIBUTION and MISATTRIBUTED.

ATTRIBUTION VERIFICATION STATE  -  USE THIS; DO NOT INVENT ONE.

Checking an attribution is a distinct verification act. It is not reception checking and not
full-text checking: it requires reading the DOWNSTREAM text and the AUDITED source - and,
where relevant, the successor - and comparing what is claimed against what each supports.

Record it as:

  CROSS-SOURCE-CONFIRMED The attribution relationship was checked against both the downstream
  text and the audited source, plus a successor or alternative source where one is implicated.

    Use this for every MISATTRIBUTED or ATTRIBUTED ELSEWHERE classification you actually
    verified.

DO NOT INVENT VERIFICATION STATES.

Use the ladder in shared_primitives.txt Section 1 plus CROSS-SOURCE-CONFIRMED above.

Live runs have produced "ESTABLISHED FROM SOURCE," "RECONSTRUCTION FROM SOURCE," and other
ad-hoc labels. Each reads as authoritative, and none is defined anywhere, so a downstream
stage cannot tell what was actually checked.

If the ladder has no state for what you did, say so in words rather than coining a label. An
undefined state is worse than a plain sentence.

For Field 3 specifically, which is a reconstruction rather than a retrieval, write:

  "author reconstruction from Field 1"

That is a description, not a verification state.

PROVENANCE-STATE DISCIPLINE  -  provenance records what happened, not what passed:

  SUPPLIED The user supplied the item, passage, document, or exact source lead for this run.
  Preserve SUPPLIED even when the item lacks a quotation, locator, or attribution check.
  Record those deficiencies under anchor eligibility.

  RETRIEVED The auditor directly accessed the item or source during this run. RETRIEVED
  records the act of direct access; it is not a claim that the item is sufficiently documented
  to anchor Field 5.

    A RETRIEVED item may therefore be:

      RETRIEVED  -  ANCHOR-ELIGIBLE RETRIEVED  -  NOT ANCHOR-ELIGIBLE: quotation missing
      RETRIEVED  -  NOT ANCHOR-ELIGIBLE: locator missing

    If the source was not directly accessed in this run and the item is being supplied from
    memory, inference, or prior exposure, use RECALLED.

  RECALLED The item was not directly accessed in this run. It is remembered, inferred from
  prior exposure, or described without current retrieval.

  NONE FOUND Means you searched and the thing does not exist. It is NOT a completeness caveat.
  "NONE FOUND for an exhaustive enumeration of every press release" is a scope note, not a
  provenance state. Write it as a scope note.

Do not use anchor eligibility to relabel provenance. A missing quotation or locator makes an
item ineligible to anchor; it does not change how the item entered the audit.

5. WHERE THE INFLATION BEGINS

ANCHORING RULE  -  CHECK BEFORE ASSIGNING ANY FAILURE LOCATION.

A failure location may be assigned only from an item that satisfies BOTH conditions:

1. Its provenance state is SUPPLIED or RETRIEVED.
2. It is ANCHOR-ELIGIBLE under the sufficiency check below.

RECALLED items may be reported in Field 4; they may not determine where the failure lives.

PROVENANCE AND ANCHOR ELIGIBILITY ARE DIFFERENT AXES.

Provenance records how the item entered the audit. Anchor eligibility records whether the item
is sufficiently documented to support a failure-location classification.

A later sufficiency check may change an item's weight or eligibility. It may NEVER rewrite its
provenance.

Examples:

- SUPPLIED  -  NOT ANCHOR-ELIGIBLE: locator missing.
- RETRIEVED  -  NOT ANCHOR-ELIGIBLE: quotation missing.
- SUPPLIED  -  ANCHOR-ELIGIBLE: quotation and locator both present.
- RETRIEVED  -  ANCHOR-ELIGIBLE: quotation and locator both present.

Do not convert a SUPPLIED item into RECALLED merely because it lacks a locator. That would
replace the factual audit trail with a record of what passed a later test.

VERIFY ELIGIBILITY; DO NOT TRUST THE EARLIER LABEL.

Before an item anchors a failure location, confirm that it contains:

- the quoted sentence - not a paraphrase and not a description of a pattern;
- a locator: document plus section or page, and URL where available;
- CROSS-SOURCE-CONFIRMED attribution where the finding is MISATTRIBUTED, ATTRIBUTED ELSEWHERE,
  or SYNTHESIS ATTRIBUTION.

Required anchoring table:

| Item | Provenance state | Quotation present? | Locator present? | Attribution cross-source-confirmed, if applicable? | Anchor eligibility |
|---|---|---|---|---|---|
| | | yes / no | yes / no | yes / no / N/A | ELIGIBLE / NOT ELIGIBLE  -  reason |

If an item lacks a quotation, locator, or required attribution check, preserve its original
provenance state and mark it NOT ANCHOR-ELIGIBLE. It may remain in Field 4 as context, but it
may not determine Field 5.

PATTERN CLAIMS DO NOT ANCHOR BY THEMSELVES.

"Frequent restatements of the form X, often citing Y" is a pattern assertion, not an
item-level quotation. Preserve its actual provenance state - SUPPLIED, RETRIEVED, or RECALLED
- but mark it NOT ANCHOR-ELIGIBLE unless item-level quotations and locators establish the
pattern.

One quoted sentence with a locator outranks any number of asserted frequencies. A bare pattern
claim cannot be checked, corrected, or disputed by a reader.

If a suspected layer has no ANCHOR-ELIGIBLE supporting item, the correct output is:

  "[Layer]  -  SUSPECTED, not established. The supporting material is not anchor-eligible:
  [quotation missing / locator missing / attribution not cross-source-confirmed / recalled
  only]. [State the specific retrieval or verification that would settle it.]"

DO NOT write "primary locus of inflation" for a layer supported only by material that is
recalled or otherwise not anchor-eligible. Confidence does not cure missing quotation,
locator, or attribution verification.

OBSERVED FAILURE THIS CLOSES:

A run correctly wrote that its downstream items were "labeled RECALLED and do not anchor
failure-location classification," then assigned CITATION / PR-MEDIA / ASSESSMENT as the
"primary locus of inflation" on exactly that material.

The rule was stated in Field 4 and violated in Field 5. Stating a discipline is not the same
as applying it at the point where it binds.

A within-source component established from the paper alone is unaffected by this rule. State
the within-source and downstream components separately, as Field 4 requires.

The specific transition where the claim exceeds what the measurement supports. Name the
passage, the citing paper, the press release sentence, or the summary.

Be precise about the move:

- "MMO progression rate" -> "gaming performance" is a construct substitution.
- "No difference in the sampled population" -> "no difference" is a scope removal.
- "Associated with" -> "causes" is an inferential upgrade.

Then classify the failure location using primitives Section 3:

  PAPER The source itself makes the leap.

  CITATION Later literature makes it.

  PR / MEDIA The communications layer makes it.

  MODEL / RETRIEVAL Summarizers reproduce the inflated version.

  MIXED Specify which layer contributes which part.

State the verification state (primitives Section 1) of every item anchoring the
classification. Use CROSS-SOURCE-CONFIRMED where an attribution relationship was verified
across sources. If the downstream chain is only RECALLED, do not assign an established
downstream failure location; use the SUSPECTED wording required above.

IMPORTANT: it is a legitimate and common finding that the source is narrow and defensible
while the downstream layer is not. Do not force a PAPER classification.

Attacking a careful paper for its press release is a category error and the fastest way for a
critique to be dismissed.

6. WHICH CLAIM IS THIS AUDIT EVALUATING?

State it in one sentence. Every prosecutor targets THIS claim.

TWO SELECTION RULES  -  both are load-bearing.

RULE 1  -  ONE CLAIM ONLY

Field 6 names a single claim. Do not bundle two claims into one field, and do not append a
second with a parenthetical or an "and the associated inference that..." clause.

A source often makes several distinct claims with different evidence bases: a measurement
claim and an attribution claim, an effect claim and a mechanism claim. Auditing two at once
reproduces, inside a single field, the exact incoherence this stage exists to prevent.

If two claims both warrant auditing, run the sequence twice.

RULE 2  -  PREFER THE MOST PRECISELY QUANTIFIED VERSION

Sources frequently state the same claim at multiple levels of precision: a general form in the
abstract and a specific quantified form in the results. Where both exist, TARGET THE
QUANTIFIED ONE.

Example:

  Abstract: "X is warmer than any year since 1400."

  Results: "X exceeds any year back to 1400 at three standard errors, or roughly a 99.7% level
  of certainty."

  Field 6 targets the SECOND.

Why: a claim with a number attached can fail a construct-validity test cleanly. You can ask
whether the stated measurement supports the stated quantity.

A claim without one can only be assessed as broadly supported or broadly unsupported, which
collapses most audits toward the same verdict. The quantified version is also where the source
has committed to something specific, which is where a defect, if present, is demonstrable
rather than arguable.

OBSERVED FAILURE THIS CLOSES:

On a live run, one map selected the abstract's unquantified version and bundled a second claim
into Field 6. The audit returned the same general verdict as two earlier ungoverned runs.

A second map on the same paper selected the quantified version alone, and the audit located a
specific defect in the source's own stated method that the other three runs did not find.

The difference was Field 6, not the prosecutor.

IF THE QUANTIFIED CLAIM IS NOT THE ONE YOU CARE ABOUT, say so and target the other one
deliberately - but record that you did, and why. The rule is a default, not a prohibition.

Choose deliberately and say why:

- Auditing the SOURCE'S claim (#2) tests whether the paper overreached.
- Auditing the DEFENSIBLE claim (#3) tests whether even the narrow version holds.
- Auditing the DOWNSTREAM claim (#4) tests the citation, PR, or model layer. The finding will
  be about that layer, NOT about the paper.

If the audit targets #4, state explicitly:

  "This audit evaluates the downstream restatement. Findings about it are not findings about
  the source document."

That one line prevents the most common and most damaging category error in the whole sequence.

RULES
-----------------------------------------------------------------

1. EXTRACT, DO NOT EVALUATE.

No severity ratings, no verdicts, no critique. The prosecutors do that. A map that arrives
pre-judged makes every downstream stage a confirmation exercise.

2. "NEITHER APPARENT" IS A VALID OUTPUT.

If the source's claim matches its measurement and the downstream restatement is faithful, say
so plainly.

A claim map that always finds inflation is not a map; it is a template. This output should
sometimes read:

  "No meaningful gap identified between measurement, claim, and downstream use."

3. PRESERVE THE SOURCE'S HEDGES EXACTLY IN FIELD 2.

Stripping them here manufactures an overclaim that the source did not make, and every
prosecutor will then audit a strawman.

4. SEARCH FOR DOWNSTREAM USES; DO NOT INVENT THEM.

Field 4 is active - look for downstream restatements rather than waiting to be handed them.
Label every item SUPPLIED / RETRIEVED / RECALLED / NONE FOUND.

RECALLED material gets its own labeled line, never a parenthetical, and may not anchor Field
5.

If nothing is retrievable, apply the field-specific provisional rule in Field 4:

- Field 4 is provisional.
- Field 5 is provisional only in its downstream component.
- Field 6 is provisional only if it targets a downstream restatement.

State whether the limitation reflects no downstream use or no retrieval capability.

5. IF THE MAP IS AMBIGUOUS, SAY SO RATHER THAN RESOLVING IT.

An honest statement such as:

  "The source states X in the abstract and the more careful Y in the discussion, and which is
  'the claim' is genuinely unclear."

is more useful than a forced single answer - and it tells the prosecutors that the map itself
needs human resolution before the sequence proceeds.
