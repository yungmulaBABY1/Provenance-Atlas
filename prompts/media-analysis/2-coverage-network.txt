COVERAGE NETWORK & SOURCE-CHAIN AUDIT — MEDIA BRANCH
RC2 CONSOLIDATED CANDIDATE
====================================================
Prosecutor stage. Document-type variant of the citation-network audit. Runs across MULTIPLE
pieces covering the SAME event or claim.

References: shared_primitives.txt Section 1 (verification states), Section 2 (finding table)
Companion to: framing_construction_audit_media.txt (single-piece construction)

-----------------------------------------------------------------
WHAT THIS AUDITS AND WHY IT'S DIFFERENT
-----------------------------------------------------------------

The single-piece framing audit asks: is this construction proportionate? That is a judgment
the auditor has to assert.

This audit supplies a BASELINE. Across five outlets covering the same event, a verb choice
stops being the auditor's characterization and becomes an observable choice: three wrote "drew
a knife," one wrote "produced a knife," one wrote "allegedly had a knife." The variance is the
evidence.

Two questions this answers that a single piece cannot:

  1. SOURCE INDEPENDENCE. If all coverage traces to one press release or one wire story, "five
     outlets reported X" is not automatically five independent confirmations. The network must
     distinguish common-source propagation, source-dependent interpretation, and claim
     amplification at the proposition level. This is the non-independence problem from the
     academic citation-network audit, with wire copy in place of a shared proxy network.

  2. SHARED CORE vs. CONSTRUCTION. Facts every outlet reports are probably established.
     Material unique to one outlet is either a scoop or a choice. The divergence map separates
     them.

WHAT THIS AUDIT CANNOT DO  -  STATE THIS IN THE OUTPUT: It maps how a story propagated and
where framings differ. It does NOT establish which framing is correct. "Twelve outlets framed
it this way, three that way" is a DISTRIBUTION, not a verdict. Majority coverage is not
evidence of accuracy  - especially when the majority shares one source. Adjudicating the
underlying facts requires primary material, which is downstream of this audit and human.

INSTRUMENT PREFLIGHT — MANDATORY FOR FORMAL / LOGGED RUNS   [TOOL-004]
-----------------------------------------------------------------

This prompt is part of the audit instrument. Establish the exact instrument version BEFORE
substantive retrieval, extraction, analysis, or verdict work begins.

A successful fetch indicator, correct repository path, branch label, plausible line count,
matching rendered metadata, or internally self-consistent page does NOT by itself establish
that the intended/current artifact was retrieved. A mutable remote reference can return a
historical representation that is internally self-consistent in every visible field.

PROMPT IDENTITY MARKERS

  - COVERAGE NETWORK & SOURCE-CHAIN AUDIT — MEDIA BRANCH
  - RC2 CONSOLIDATED CANDIDATE
  - [FAIL-MB-017]
  - PROMINENCE AND PACKAGING
  - [FAIL-MB-018]
  - SEMANTIC EQUIVALENCE AND EARNEDNESS GATE

These markers confirm the prompt family / expected structural features. They do NOT by
themselves establish version currency: an older version may share the same title or markers.

1. RECORD THE INSTRUMENT ACTUALLY IN CONTEXT.

   Record, where available:

   - canonical prompt path or supplied filename;
   - retrieval form: PASTED / ATTACHED / IMMUTABLE REMOTE / MUTABLE REMOTE;
   - requested branch or ref;
   - intended immutable commit/ref, if the run claims a repository version;
   - resolved commit SHA;
   - resolved blob/content hash, or a locally computed cryptographic content hash;
   - exact line count and byte count;
   - prompt identity markers present / absent.

   If a pasted or attached artifact is itself the declared instrument under test, its computed
   content hash may serve as its identity. Do not claim it is the current canonical repository
   version unless that relationship is independently established.

2. MUTABLE-REFERENCE / CURRENCY RULE.

   A path such as /blob/main/, /blob/master/, latest, or another moving branch/ref is a LOCATOR,
   not an immutable version identity.

   Ordinary exploratory work may use a mutable locator with the limitation preserved.

   A FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE run that claims the current repository
   instrument must establish an immutable intended identity independently of the mutable-content
   fetch. Acceptable examples include:

   - an operator-supplied immutable commit permalink;
   - a branch-head / repository-history lookup independent of the content retrieval, followed by
     retrieval of the file at that immutable commit;
   - a second retrieval path that does not reuse the same cache/index, confirmed against an
     immutable commit/blob identity.

   A commit/hash/line-count reported only by the SAME potentially stale rendered representation
   is NOT independent currency evidence.

   If no independent immutable anchor can be established and no explicit collision is observed,
   classify:

     INSTRUMENT VERSION UNVERIFIED

   Such a run may be exploratory but may not count as formal regression or benchmark evidence
   for a claimed canonical version.

3. VERSION-COLLISION ATTRIBUTION GATE.

   If the retrieved representation disagrees with an expected hash, immutable ref, size, line
   count, marker set, or independently established version, classify only:

     VERSION COLLISION — UNRESOLVED

   A failed identity check proves a VERSION MISMATCH. It does NOT establish where the stale
   representation lives. Do NOT conclude from the conflicting retrieval alone:

     REPOSITORY STALE
     RETRIEVAL STALE
     LOCAL COPY STALE
     OPERATOR COPY STALE

   Attribution requires a SECOND, INDEPENDENT discriminator, such as:

   - an immutable commit/blob lookup;
   - repository/file history;
   - a second retrieval path that does not reuse the same cache/index;
   - direct operator confirmation supported by an immutable identity;
   - a locally supplied file whose hash can be compared independently.

   Internal self-consistency is NOT an independent discriminator. A stale representation may
   have a mutually consistent path, branch label, line count, byte size, line gutter, content,
   and rendered repository metadata because all were produced from the same stale snapshot.

4. DISPOSITION.

   FORMAL / LOGGED / BENCHMARK / REGRESSION / FIXTURE RUN:
     - IDENTITY CONFIRMED against the intended immutable instrument -> continue.
     - VERSION COLLISION — UNRESOLVED -> STOP before substantive execution.
     - INSTRUMENT VERSION UNVERIFIED -> exploratory execution may occur, but the run may not be
       logged as evidence for the claimed canonical instrument.

   ORDINARY EXPLORATORY RUN:
     - May continue with INSTRUMENT VERSION UNVERIFIED when no collision is observed.
     - If a collision is observed, do not make claims about repository/instrument state until
       the collision is independently resolved.

5. REQUIRED RUN-HEADER LINE.

   Emit this before the substantive body:

   INSTRUMENT PREFLIGHT: [path/file] @ commit [SHA/UNAVAILABLE] | blob/hash
   [HASH/UNAVAILABLE] | [N] lines | [N] bytes | markers [PRESENT/ABSENT] |
   [IDENTITY CONFIRMED / INSTRUMENT VERSION UNVERIFIED /
   VERSION COLLISION — UNRESOLVED]

   If VERSION COLLISION — UNRESOLVED is returned, also state the conflicting identities and the
   independent discriminator required to resolve them. Do not silently choose one.

GOVERNING RULE:

  A failed identity check proves a version mismatch, not where the mismatch lives.

=================================================================
PRIOR DECOMPOSITION AND MAPPING — MANDATORY
=================================================================

Run this block whenever an operator prior is supplied.

Do not evaluate an operator prior as one thematic bundle.
Before retrieval, decompose it into the smallest independently testable
propositions while preserving the operator's original wording, quantifiers,
subjects, objects, comparison classes, conditions, and epistemic claims.

If the operator supplies no prior, write:

  PRIOR SOURCE: NONE
  PRIOR MAPPING: NOT APPLICABLE

and continue in neutral coverage mode. Do not generate a model prior unless a
specific ambiguity cannot otherwise be interpreted. The default is NONE.

REQUIRED PRIOR MAP

| Prior ID | Exact operator proposition | Proposition type | Quantifier / threshold | Exact coverage object | Unit of analysis | Eligible denominator rule | Retrieval question | Required evidence | Resolution |
|---|---|---|---|---|---|---|---|---|---|

PROPOSITION TYPES

1. COVERAGE-DISTRIBUTION PREDICTION
   Predicts how many outlets will include, omit, foreground, subordinate,
   attribute, update, or frame something.

2. COVERAGE-CONSTRUCTION PREDICTION
   Predicts how a fact, actor, cause, controversy, comparison, or event object
   will be described.

3. FACTUAL PREMISE
   Makes a claim about the underlying event or record rather than the coverage.

4. COUNTERFACTUAL OR COMPARATOR CLAIM
   Predicts how a different person, identity, institution, or reversed case
   would be treated.

5. CAUSAL OR MOTIVE CLAIM
   Attributes a reason for outlet, institutional, or actor behavior.

6. NORMATIVE JUDGMENT
   States that treatment was fair, unfair, proportionate, absurd, justified,
   or equivalent.

MANDATORY RULES

A. PRESERVE QUANTIFIERS

Do not silently replace:

- "most" with "all";
- "many" with "most";
- "rarely" with "never";
- "largely omit" with "completely omit";
- "mention" with "make the governing frame";
- "foreground" with "include anywhere."

Define the operational threshold before retrieval and before examining the
result.

Unless the operator supplies another threshold:

- ALL = 100%
- NEARLY ALL = at least 80%
- MOST = more than 50%
- MANY = a substantial non-trivial share, operationalized before retrieval;
  default to at least 40% or at least three eligible pieces, whichever better
  preserves the ordinary meaning for the corpus size; state the chosen rule
- SOME = at least two eligible items, where the corpus permits
- FEW = less than 25%
- NONE = 0%

The threshold must not be changed after the evidence is counted.

B. DEFINE DENOMINATOR ELIGIBILITY

State which pieces are capable of answering each proposition.

Examples:

- an omission claim requires FULL-TEXT-confirmed pieces;
- a headline-presence claim may use headline-only pieces;
- a foregrounding claim requires headline, lede, or upper-body access;
- an update-failure claim requires version or update evidence;
- a conditional claim about pieces that mention culture war uses only pieces
  that actually mention culture war.

Do not place an ineligible source in the denominator.

C. DO NOT MERGE DISTINCT OBJECTS

Treat the following as separate propositions unless the operator explicitly
joins them:

- whether a disputed history is mentioned;
- whether institutional enablement is mentioned;
- whether race is mentioned;
- whether race governs the article's framing;
- whether culture-war context is mentioned;
- whether that context is described accurately;
- whether a comparator is mentioned;
- whether the comparator claim is substantively true.

Evidence against one proposition does not weaken another.

D. SEPARATE COVERAGE CLAIMS FROM UNDERLYING-TRUTH CLAIMS

A corpus may confirm that outlets omitted a comparator without establishing that
the comparator would actually receive different treatment.

Resolve separately:

- COVERAGE RESULT: Was the comparator raised?
- SUBSTANTIVE RESULT: Does matched evidence support the comparator?

Do not mark a coverage prediction unconfirmed merely because the substantive
counterfactual remains untested.

E. ALLOW ONE PRIOR TO PRODUCE MULTIPLE LEADS

A single operator sentence may contain several propositions. Assign each its own
Prior ID and Lead ID.

Example:

  "Most will mention it as part of the culture war, but not accurately describe
  why."

must become at least:

- P1: Most eligible pieces mention culture-war context.
- P2: In pieces mentioning that context, it is materially relevant rather than
  incidental.
- P3: In pieces firing the context, the stated explanation omits or misstates
  the mechanism identified by the operator.

Each receives its own denominator, retrieval question, and resolution.

F. PRESERVE CONDITIONAL STRUCTURE

For a prior of the form "where X occurs, Y follows," test Y only within pieces
where X occurs.

Do not test the consequent against the entire corpus.

G. MATCH EVIDENCE TO THE EXACT PREDICATE

A mention of Cambridge's immediate defence does not satisfy a prior about years
of institutional enablement and elevation.

A piece satisfies a broader proposition only if it materially addresses the
relevant chain, such as:

- promotion or appointment history;
- awards, honorary degrees, platforms, or institutional celebration;
- earlier warnings or contradictory evidence;
- institutional defence or shielding;
- failure to investigate;
- later reversal after scrutiny.

Do not substitute adjacent evidence for the exact audit object.

H. TRANSLATE LOADED LANGUAGE WITHOUT WEAKENING THE PREDICTION

Preserve the original wording and create an auditable evidentiary translation.

Example:

  "history of lies"

may become:

  "documented disputed, corrected, contradicted, denied, or unsupported claims."

The audit may refuse the moral label while still testing the underlying
coverage-distribution prediction.

I. RESOLVE EACH PRIOR BEFORE AGGREGATING

Use:

- CONFIRMED
- PARTIALLY CONFIRMED
- REFRAMED
- NOT CONFIRMED
- INSUFFICIENT EVIDENCE

PARTIALLY CONFIRMED applies only when the same proposition is supported in part.

Do not use "partial" merely because some propositions in a multi-part prior were
confirmed and others were not.

Required proposition-level result:

| Prior ID | Exact proposition | Result | Corpus count / evidence | Qualification |
|---|---|---|---|---|

Only after every proposition is resolved may the audit issue one aggregate:

- STRONG MAPPED MATCH
- SUBSTANTIAL MAPPED MATCH
- MIXED MAPPED RESULT
- WEAK MAPPED MATCH
- NO MAPPED MATCH
- INSUFFICIENT TO ASSESS

The aggregate must summarize the proposition-level results. It may not replace
them.

J. COUNTEREXAMPLES NARROW; THEY DO NOT AUTOMATICALLY FALSIFY

For every non-universal distributional prediction, report:

- number matching;
- number not matching;
- eligible denominator;
- whether the stated threshold was met.

Do not describe a prediction as overbroad merely because it allowed exceptions
and exceptions occurred.

PRIOR-MATCH OUTPUT

For every operator prior, output:

ORIGINAL PRIOR:
[verbatim or minimally normalized text]

DECOMPOSED PROPOSITIONS:
[list of Prior IDs]

PROPOSITION-LEVEL RESULTS:
[table]

AGGREGATE MAPPED RESULT:
[result]

WHAT MATCHED:
[exact propositions]

WHAT DID NOT MATCH:
[exact propositions]

WHAT REMAINS UNTESTED:
[factual, causal, motive, normative, or comparator claims the corpus cannot
resolve]

MAPPING INTEGRITY CHECK

- Were any distinct propositions merged?
- Were any quantifiers strengthened?
- Was "mention" confused with "foreground" or "governing frame"?
- Was a coverage prediction confused with an underlying-truth claim?
- Was a conditional prior tested against the wrong denominator?
- Was a counterexample incorrectly treated as falsifying a non-universal
  prediction?
- Was adjacent evidence substituted for the exact object of the prior?

If any answer is YES, revise the mapping before issuing the verdict.

EXECUTION GATE

The Investigation Register may not begin until:

- every supplied prior has a Prior ID;
- compound priors have been split;
- each quantifier and threshold has been stated;
- each eligible denominator rule has been stated;
- conditional priors preserve their condition;
- corpus-level claims have been separated from single-event claims.

If this mapping is not completed, Section E2 must state:

  PRIOR MAPPING FAILURE — PRIOR-MATCH VERDICT INVALID

INVESTIGATION REGISTER AND LEAD ORIGIN
-----------------------------------------------------------------

The audit may begin with no hypothesis, an operator-supplied hypothesis, or a
lead generated by an earlier stage. Retrieval may also produce a bounded
emergent lead.

Tag every lead using exactly one origin:

  OPERATOR
  PRIOR-STAGE GENERATED
  EXTRACTOR GENERATED
  RETRIEVAL EMERGENT

For every lead, record:

| Lead ID | Origin | Initial formulation | Trigger | Retrieval question | Resolution |
|---|---|---|---|---|---|

GOVERNING RULE:

  Operator hypotheses influence retrieval, not conclusions.
  Retrieval influences conclusions.

A lead is not a finding. It may guide retrieval. It may not lower the
evidentiary threshold.

If no lead exists, continue in neutral coverage mode. Do not manufacture one.

-----------------------------------------------------------------
BALANCED HYPOTHESIS RETRIEVAL
-----------------------------------------------------------------

For every lead, perform a support-side and weakening-side check before
resolution.

FULL BALANCED RETRIEVAL is mandatory when the lead is:
- OPERATOR-supplied or derived from a mapped operator prior;
- PRIOR-STAGE GENERATED;
- load-bearing or contested;
- capable of materially changing retrieval scope, finding ownership, severity,
  or the verdict.

For those leads:

1. Translate the lead into one or more falsifiable retrieval questions.
2. Document the search performed for evidence that would SUPPORT it.
3. Document the search performed for evidence that would WEAKEN, REFRAME, or
   FALSIFY it.
4. Apply comparable effort to both search directions.
5. Do not resolve the lead until both search paths are documented.
6. Searching only for confirming evidence is a procedural failure.

| Lead ID | Supporting search | Weakening / disconfirming search | Evidence recovered | Missing evidence |
|---|---|---|---|---|

For a non-load-bearing RETRIEVAL EMERGENT lead, a compact paired check is enough:
record the best supporting item and the best weakening item or state why one
side could not be tested. Do not run a full search dossier unless the lead
becomes load-bearing.

Absence of contradicting evidence is not confirmation.

-----------------------------------------------------------------
BOUNDED EMERGENT LEADS
-----------------------------------------------------------------

A RETRIEVAL EMERGENT lead may be introduced only when required to explain an
inconsistency, omission, attribution chain, framing divergence, or dependency
already identified within the current audit object.

It may not broaden the audit object.

An emergent lead is invalid when it:
- follows an interesting but non-load-bearing tangent;
- opens a new controversy not required to resolve the current object;
- expands retrieval merely because adjacent material was discovered;
- substitutes a broader target for the supplied target.

| Trigger inside current object | Why necessary | Scope boundary | Supporting search | Weakening search |
|---|---|---|---|---|

If the lead cannot state its scope boundary in one sentence, do not admit it.

-----------------------------------------------------------------
SHARED INNOCENT-EXPLANATION TEST
-----------------------------------------------------------------

Before reporting any asymmetry, selection, divergence, or failure, test whether
it can instead be explained by a non-directional constraint.

Candidate explanations include:
- breaking-news uncertainty;
- publication timing;
- legal or privacy restrictions;
- attribution limits;
- headline economy;
- article length or format;
- incomplete investigation;
- wire dependence;
- story assignment;
- missing primary material;
- genuine scoop;
- disputed facts;
- house style or professional convention.

| Candidate explanation | Evidence supporting it | Evidence weakening it | Residual difference |
|---|---|---|---|

An innocent explanation is not automatic acquittal. Report only the residual
difference that survives the test.

-----------------------------------------------------------------
REFRAMED RESOLUTION STATE
-----------------------------------------------------------------

Use REFRAMED when the originating concern was directionally meaningful but the
retrieved evidence identifies a materially different mechanism, location,
scope, role, causal step, or formulation.

When using REFRAMED, state:
1. ORIGINAL FORMULATION
2. EVIDENCE-SUPPORTED REFORMULATION
3. WHAT MOVED
4. WHY THE OTHER RESOLUTION STATES ARE LESS ACCURATE

General investigation-lead resolution vocabulary:
  CONFIRMED
  PARTIALLY CONFIRMED
  REFRAMED
  NOT CONFIRMED
  INSUFFICIENT EVIDENCE

Section D2 retains its own formal cross-branch vocabulary:
CONFIRMED / FALSIFIED / RECLASSIFIED / NETWORK-WIDE /
STILL UNRESOLVED / NO EVIDENCE.

A D2 RECLASSIFIED result may note that the underlying concern was REFRAMED, but
the formal D2 value remains RECLASSIFIED.

COMPACT MEDIA PRIMITIVE
-----------------------------------------------------------------

[MEDIA-P1] CAUSAL-ROLE AXES + GATES

CANONICAL RULE. This compact copy and every local execution copy must move
together. Local sections may add examples, but may not rename, narrow, broaden,
or change the disposition of these axes and gates.

Six axes. For each, extract the assignment the TEXT makes. Leave the axis blank
when the text supplies no usable assignment and the absence itself is not the
object of analysis. When non-assignment is materially part of the construction,
record the applicable null state rather than silently leaving it blank.

Do not infer an assignment from the headline alone. An assignment explicitly
stated in a headline may be recorded as a headline assignment; do not infer an
unstated cause, blame, role, or motive from it.

Never infer cause, blame, motive, role, or status from names, appearance,
employer, or location.

EVENT CLASSIFICATION
  The noun or frame assigned to the event itself. The noun is a claim. Where the
  absence of classification is materially relevant, record UNCLASSIFIED.

CAUSE
  Why the event happened: stated, alleged, or inferred motive; the explanation
  supplied for the event; or whether the text assigns no cause. Where materially
  relevant, record NO CAUSE ASSIGNED.

ROLE-AND-STATUS
  Who is cast as agent, victim, perpetrator, beneficiary, cost-bearer,
  bystander, official, whistleblower, defendant, or complainant.

BLAME / RESPONSIBILITY
  Who or what is assigned fault, including whether responsibility is
  individualized, institutionalized, diffused, or left unassigned.

REMEDY
  Whether a fix or solution is offered, whose fix it is, and who is called to
  act. Where materially relevant, record NO REMEDY FRAMED.

LEADERSHIP / POLICY
  How leadership decisions or policy are characterized, including competent,
  failing, humane, authoritarian, negligent, necessary, or ineffective
  characterizations, whether stated directly, appositionally, or through a
  source.

EPISTEMIC LEVEL - CAUSE AND BLAME

Classify every CAUSE and BLAME assignment:

  DOCUMENTED
    Direct statement, verified communication, or established record.

  OFFICIALLY-ALLEGED
    Law enforcement, complaint, indictment, or institutional finding.

  SOURCE-INFERRED
    Witness, advocate, expert, or interested party's inference.

  OUTLET-INFERRED
    The article's own synthesis.

  UNKNOWN
    Evidence insufficient.

Test for silent upward movement: an alleged cause restated as documented, or a
source's inference appearing later in outlet voice. Apply the ladder separately
to CAUSE and BLAME.

VERB-AS-TRACE
(for wording-derived candidates that survive the Semantic Equivalence and Earnedness Gate)   [FAIL-MB-018]

In the Coverage Network branch, apply VERB-AS-TRACE only to lexical/formulation
candidates that survived the Semantic Equivalence and Earnedness Gate as
MATERIAL OUTLIERS. Do not apply it to candidates already resolved as REGISTER
VARIANCE or EARNED SPECIFICITY. This limitation does not prevent D-ROLE from
independently discovering a substantive causal-role assignment difference.

A verb or descriptor is reportable as causal-role framing only when it MOVES an
assignment on one of the six axes.

Examples:

- "breach" assigns migrant agency against a defended boundary;
- "waved through" reassigns cause to an authority;
- "pour" or "surge" can classify the event as flood-like mass movement.

A lexical difference that moves no assignment is REGISTER variance. Record it
as register only; do not report it as framing.

This test is distinct from the causal-bridge test. VERB-AS-TRACE asks what
causal-role assignment the language makes. The causal-bridge test asks whether
the WHY of a sequence is present or removed.

BRANCH-SPECIFIC LAYERS

Single-piece branch:
  Apply the mirror and flip guard to these axes. Cause, blame, and victim-role
  assignments are especially prior-sensitive. The branch must be able to
  decline to find a causal-role failure.

Coverage branch:
  Add CHOSEN vs. INHERITED, TEXT-READ vs. HEADLINE-ONLY, and the genre
  not-firing condition. These determine whose framing is being observed and
  whether the sample can support a divergence finding.

-----------------------------------------------------------------
COMPANION RETRIEVAL
-----------------------------------------------------------------

The initial event-keyword packet may omit the material that supplies the
coverage's inherited historical, causal, political, moral, organizational, or
classificatory frame.

When Fixed-packet mode is NO, retrieve companion material meeting at least one
of these triggers:

MECHANICAL TRIGGERS
  A. LINKED OR CITED
     The audited piece directly links, cites, embeds, quotes, or names the item.

  B. MATERIALLY RELIED UPON
     The audited piece depends on the item for a load-bearing factual,
     chronological, legal, causal, or attribution claim.

JUDGMENT-REQUIRING TRIGGERS
  C. INHERITED FRAME
     The item supplies a historical analogy, precedent, moral comparison,
     political frame, organizational characterization, or event classification
     materially used by the audited coverage.

  D. DEMONSTRABLY UPSTREAM
     Publication sequence, explicit attribution, repeated phrasing, or source
     tracing shows that the item is upstream of a later framing choice.

Mechanical triggers qualify automatically when the item can be obtained.

Judgment-requiring triggers must satisfy all of the following:

  1. Name the exact framing claim or classification the companion item is needed
     to evaluate.
  2. Identify the passage in the audited coverage that materially relies on it.
  3. State what the companion item could confirm, weaken, reframe, or falsify.
  4. Bound the retrieval to that dependency.
  5. Stop once the dependency can be resolved or further retrieval ceases to
     change its evidentiary status.

Do not retrieve an item merely because it is topically adjacent, politically
interesting, or likely to contain useful criticism.

Required table:

| Companion item | Trigger (A-D) | Dependency in audited coverage | Retrieval result | Effect on finding |
|---|---|---|---|---|

GOVERNING RULE:

  Retrieve inherited framing before auditing inherited framing.

PACKET-BOUNDARY OUTPUT

State:
- Initial packet boundary
- Companion items added
- Why each qualified
- Material sought but unavailable
- Which findings would have differed under the initial packet alone

When Fixed-packet mode is YES, do not widen retrieval. Instead state which
potential companion dependencies remain untested because the packet is closed.

-----------------------------------------------------------------
CONTEXT-SUPPORTED IDENTITY INFERENCE
-----------------------------------------------------------------

An ideological, organizational, movement, or group characterization may be
supported when multiple observable indicators in the retrieved material converge
on that characterization.

Do not import general background knowledge about who typically uses a tactic,
symbol, slogan, organizational form, or style unless that background material
was separately retrieved and shown to be relevant.

INFERENCE LADDER

Classify the inference at exactly one level:

  1. VERIFIED ORGANIZATIONAL IDENTITY OR CONTROL
     Direct evidence establishes identifiable membership, authorization,
     leadership, command, governance, formal affiliation, organizational
     responsibility, or equivalent control.

  2. CONTEXT-SUPPORTED IDEOLOGICAL ALIGNMENT
     Multiple retrieved indicators support alignment with a recognizable
     ideological or movement framework, but formal identity or command is not
     established.

  3. CONTEXT-SUPPORTED TACTICAL OR MOVEMENT RESEMBLANCE
     Retrieved conduct, symbols, slogans, structure, or tactics materially
     resemble a recognizable movement pattern, but alignment and formal
     affiliation remain unverified.

  4. WEAK CONTEXTUAL RESEMBLANCE
     One or more indicators suggest resemblance, but the evidence is limited,
     ambiguous, heterogeneous, or nonexclusive.

  5. UNSUPPORTED ATTRIBUTION
     The retrieved record does not support the proposed characterization.

FORMAL-CONTROL EVIDENCE FLOOR

No combination of slogans, symbols, rhetoric, tactics, political alignment,
movement resemblance, or accumulated lower-rung indicators may establish rung 1
by itself.

Rung 1 requires direct evidence of membership, leadership, authorization,
command, governance, organizational responsibility, formal affiliation, or an
equivalent organizational connection.

If that evidence is absent, the classification may not exceed rung 2.

MANDATORY INFERENCE-PARITY CHECK

Apply this check to every affirmative classification at rungs 1 through 4.
Rung 5 is exempt because it makes no affirmative inference.

1. ENUMERATE THE ORIGINAL INDICATORS
   List every retrieved indicator supporting the classification.

2. STATE THE EXACT INFERENCE
   Specify the rung and whether the finding asserts control, alignment,
   resemblance, or weak resemblance.

3. BUILD THE MIRROR CANDIDATE
   Identify the strongest materially comparable inference in the opposite
   ideological, political, organizational, or institutional direction that the
   same retrieved record might license.

4. APPLY THE SAME LADDER
   Enumerate the mirror indicators and classify the mirror candidate using the
   same five-rung ladder. Do not merely state that the rule could apply.

5. EXPLAIN ANY DIFFERENT RESOLUTION
   Identify the material evidentiary distinction. Political valence,
   familiarity, presumed legitimacy, or agreement with the cause are not
   evidentiary distinctions.

6. REMOVE DIRECTIONAL FRAMING
   Reassess the original indicators without relying on the political,
   ideological, or institutional direction of the classification.

7. CONSEQUENCE
   If parity fails, downgrade the original inference to the highest rung
   independently supported after directional framing is removed. Do not apply
   an automatic one-rung decrement.

   A parity failure may produce:
   - one-level downgrade;
   - multi-level downgrade;
   - UNSUPPORTED ATTRIBUTION.

   A finding that fails parity may not remain load-bearing unless its revised
   classification independently supports the finding.

COUNTING UNIT - STATE IT BEFORE GIVING ANY NUMBER.   [FAIL-MB-008][FAIL-MB-009]

"Independent source" is ambiguous and the ambiguity is not resolvable by judgment. Count at
BOTH levels below and report BOTH as DESCRIPTION. Neither whole-coverage number carries a
claim-amplification verdict. Proposition-level network classification is determined by the
per-fact table further down. Do not skip that table.

LEVEL 1 - REPORTING ORGANIZATIONS (descriptive; comparatively stable) How many distinct
organizations produced original reporting - sent a journalist, conducted an interview,
obtained a document, or made a direct observation? An outlet that only republishes or
synthesizes does not count.

LEVEL 2 - UPSTREAM INFORMATION ORIGINS (descriptive; granularity-sensitive) How many
distinct origins does the reported material trace back to? Report it, but DO NOT read the
Level-1-vs-Level-2 relationship as a finding. Level 1 counts only original reporters (often
few); Level 2 counts every upstream origin (often many), so Level 2 routinely EXCEEDS Level
1. That direction carries no meaning, and the whole-coverage count is not comparable
run-to-run - the same coverage is defensibly counted at very different granularities.

WHOLE-COVERAGE RATIO - DESCRIPTIVE ONLY. NOT AN AMPLIFICATION VERDICT. pieces / Level 2 is
granularity-sensitive and misleads. A ratio near or below 1 is NOT evidence of independence:
a story can trace every disputed number to one source while its total origin count looks
large. State the number if you wish; it may not support any corroboration or claim-
amplification conclusion. The next table determines proposition-level network classification.

SINGLE-ORIGIN PROPAGATION VS. CLAIM AMPLIFICATION — LOAD-BEARING STEP, DO NOT SKIP

A fact appearing in many pieces but tracing to one origin is SINGLE-ORIGIN
PROPAGATION. That is a source-chain description, not automatically an
amplification finding.

Source dependence describes where information came from.
Amplification describes what repetition does to the apparent evidentiary weight
of a contestable claim.

Build this table for every load-bearing or contested fact:

| Fact or claim | Pieces asserting it | Origins located | Origin completeness | Single-origin confirmed? | Origin authority | Claim contestability | Attribution behavior | Apparent-corroboration risk | Network classification |
|---|---:|---:|---|---|---|---|---|---|---|


ORIGIN COMPLETENESS — DO NOT TURN POSITIVE TRACING INTO AN ABSENCE CLAIM

"Origins located" is a positive count and may be reported whenever the origins
are actually retrieved or preserved.

"Single-origin confirmed" is stronger: it asserts that no additional origin
appears in the eligible source range. Set it to YES only when retrieval is
sufficiently complete to support that negative determination.

Use:

- COMPLETE — eligible source range is sufficiently retrieved for origin
  exclusivity.
- PARTIAL — one or more relevant pieces or upstream dependencies are incomplete.
- UNKNOWN — completeness cannot be assessed.

When completeness is PARTIAL or UNKNOWN:

- report the origins actually located;
- write SINGLE-ORIGIN CONFIRMED: NOT ESTABLISHED;
- do not convert the located-origin count into an exclusivity claim;
- classify the network behavior from the evidence actually available, using
  CHAIN UNRESOLVED where the missing origin structure is load-bearing.

This rule preserves positive source tracing under partial retrieval without
weakening the absence-claim evidence floor.

ORIGIN AUTHORITY IS PROPOSITION-SPECIFIC

A source may be authoritative for the occurrence of its own act, statement,
decision, filing, publication, or status while remaining non-authoritative for:

- external facts;
- causal explanations;
- motive;
- responsibility;
- legality;
- justification;
- scale;
- or the truth of allegations about another actor.

PERMITTED NETWORK CLASSIFICATIONS

COMMON-SOURCE PROPAGATION

Use when the origin is directly authoritative about an act, statement,
decision, proceeding, publication, filing, or status within its control.

Examples:

- a person announces their resignation;
- an institution announces that it opened an investigation;
- a court reports that it entered an order;
- an agency publishes its own policy.

Common-source propagation is non-independent reporting. It is not claim
amplification merely because only one origin exists.

SOURCE-DEPENDENT INTERPRETATION

Use when the underlying act or status is established, but its cause, meaning,
motive, responsibility, or significance comes from one interested or
non-independent source.

Example:

- the resignation occurred, but the resigning party's explanation of why it
  occurred remains that party's account.

Do not treat repetition of the interpretation as independent confirmation.

CLAIM AMPLIFICATION

Use only when ALL are true:

1. The claim concerns a disputed, uncertain, inferential, causal, quantitative,
   reputational, classificatory, or externally verifiable proposition.
2. The originating source is not independently authoritative to establish that
   proposition merely by stating it.
3. Multiple pieces repeat the claim from the same origin in a way that may create
   the appearance of cross-outlet corroboration.

Examples:

- disputed casualty, attendance, financial, crime, prevalence, or scale figures;
- allegations of misconduct;
- claims about motive, responsibility, affiliation, or control;
- analytical findings produced by one investigation;
- causal explanations;
- contested event classifications.

CROSS-OUTLET CORROBORATION

Use only where the fact has two or more genuinely independent origins capable of
supporting the proposition at issue.

CONTESTED

Use when retrieved origins materially conflict.

CHAIN UNRESOLVED

Use when the immediate or upstream origin cannot be established well enough to
classify the network behavior.

APPARENT-CORROBORATION RISK

Code:

- LOW
- MODERATE
- HIGH

A plainly attributed repetition such as "Arday said the scrutiny was racially
motivated" generally carries lower apparent-corroboration risk than multiple
outlets stating "the scrutiny was racially motivated" in outlet voice.

RULES FOR THE TABLE

- Count origins PER FACT and distinguish ORIGINS LOCATED from origin completeness.
- Do not pool facts.
- Do not average a single-origin claim against a well-corroborated one.
- Many pieces / one origin is not automatically amplification.
- A single statement may contain multiple proposition types:
  - the speaker made the statement: COMMON-SOURCE PROPAGATION;
  - the explanation inside it: SOURCE-DEPENDENT INTERPRETATION or CLAIM
    AMPLIFICATION.
- Preserve attribution behavior. Attribution that weakens or disappears across
  the network increases apparent-corroboration risk.

FINDING CONSEQUENCES

- COMMON-SOURCE PROPAGATION: ordinarily descriptive only.
- SOURCE-DEPENDENT INTERPRETATION: eligible for a finding only when attribution
  weakens, disappears, or the interpretation becomes load-bearing.
- CLAIM AMPLIFICATION: eligible for a source-chain finding.
- CROSS-OUTLET CORROBORATION: may weaken or defeat an amplification concern.
- CHAIN UNRESOLVED: capped and may not anchor a strong finding.

REQUIRED STATEMENT — use this form:

"Across [P] pieces, the load-bearing facts trace to these located origins:
[fact — pieces / origins located / origin completeness / classification; ...].
[N] facts are COMMON-SOURCE PROPAGATION, [M] are SOURCE-DEPENDENT
INTERPRETATIONS, and [K] qualify as CLAIM AMPLIFICATION. Only the last category
represents apparent cross-outlet agreement that may falsely resemble independent
confirmation. Identify any source-dependent interpretation whose attribution
weakened or disappeared across the network, and any fact for which
SINGLE-ORIGIN CONFIRMED is NOT ESTABLISHED."

SOURCE-CHAIN STATUS  -  a SEPARATE axis from verification state (Do NOT use
RECEPTION-CONFIRMED here. In shared_primitives Section 1 that means a source's own later
reception was checked  -  replies, replications, corrections. Comparing an article to a
press release is source-chain verification, a different operation entirely.)

  CHAIN-CONFIRMED ... primary source material or wire copy was available and directly
  compared against the piece CHAIN-INFERRED .... chain inferred from attribution,
  publication timing, or textual similarity, without the upstream document in hand
  CHAIN-PROVISIONAL . upstream source cannot be established

VERIFICATION STATE OF THE EVIDENCE USED  -  media branch subset:

  LOCATED ..................... the item exists; content unverified
  FULL-TEXT-CONFIRMED ......... you read the full source and it supports the claim
  CROSS-OUTLET-CORROBORATED ... the fact is supported by 2+ INDEPENDENT origins
                                across outlets; state the per-fact origin count
  CONTESTED ................... outlets report it incompatibly
  PROVISIONAL ................. asserted from memory, or source not retrieved

  RECEPTION-CONFIRMED IS NOT USED IN THIS BRANCH. In shared_primitives Section 1 it means a
  source's own scholarly reception was checked  -  replies, replications, corrigenda. News
  coverage does not have reception in that sense. If you reach for it, you want
  CROSS-OUTLET-CORROBORATED or CHAIN-CONFIRMED.

  CROSS-OUTLET-CORROBORATED MUST CARRY THE PER-FACT ORIGIN COUNT. A fact may be labeled
  CROSS-OUTLET-CORROBORATED only if it has 2+ INDEPENDENT origins capable of supporting the
  proposition at issue on its own row in the per-fact table. A fact carried by many outlets
  but tracing to ONE origin is SINGLE-ORIGIN PROPAGATION and must be classified under the
  Section B taxonomy. It is not automatically CLAIM AMPLIFICATION and may not be called
  corroborated. State the per-fact origin count and network classification alongside every
  use of this label.

Apply this subset separately to the documents supporting a finding. The two axes combine  -
e.g. the police statement may be FULL-TEXT-CONFIRMED while the outlet's dependence on it is
only CHAIN-INFERRED.

Report both when both apply.

AVAILABILITY MATRIX  -  REQUIRED BEFORE CALLING ANYTHING "SELECTION"

Outlets publish at different times with different information. Comparing a later piece (more

| Fact / source material | Available when A published? | B? | C? | D? |

RULE: a fact may be called SELECTION only if it was AVAILABLE before that piece published and

ABSENCE-CLAIM EVIDENCE FLOOR

Claims using "only," "none," "no outlet," "unique," "absent," "omitted," or an
equivalent absence / exclusivity formulation require FULL-TEXT-CONFIRMED status
for every source included in the claimed range.

A HEADLINE-ONLY, SNIPPET-ONLY, unretrieved, or otherwise partial source:

- may support a presence claim about the preserved text;
- may not support absence, omission, exclusivity, source-distribution
  completeness, sequencing completeness, or "only / none" claims;
- must be excluded from the denominator of the absence claim.

If excluding partial sources makes the claimed range incomplete, the absence
claim is UNAVAILABLE, not merely PROVISIONAL.

Do not convert silence in a summary, snippet, reconstruction, or prior audit into
evidence that the underlying article lacked the material.

State availability basis for each: known (documented release time) / inferred (other coverage
carried it earlier) / unknown. Unknown availability caps the finding at PROVISIONAL.


MANDATORY AVAILABILITY CITATION FOR SELECTION CLAIMS

Any finding that uses "selection" or an equivalent formulation — including:

- selectively amplified;
- chose to include;
- chose to omit;
- foregrounded despite availability;
- withheld despite availability;

must cite an explicit Availability Matrix row inside the finding itself.

Use this form:

  AVAILABILITY ROW CITED:
  [fact or source] available by [date/time] — [outlet] published [date/time].

The cited row must establish that the material was available before the outlet
published.

Without this citation, the audit may describe:

- inclusion;
- non-inclusion;
- source-distribution difference;
- availability unknown;
- timing artifact;
- timing untested.

It may not call the difference selection.

THE KEY ASYMMETRY: a fact available to all outlets  -  present in the primary source or in
earlier coverage  -  that some include and some omit, where the pattern correlates with
framing. That is selection, and unlike a single-piece omission finding, it is demonstrable
rather than asserted.

A second, distinct object is also demonstrable. Where a fact is carried anywhere
in a FULL-TEXT-CONFIRMED piece but is absent from a more prominent layer under
comparison — or where competing facts or factual dimensions receive materially
different placement priority across headline, lede, and body — the piece itself
establishes possession of the fact. No cross-piece availability reconstruction is
required. That object is PROMINENCE, not SELECTION, and it is governed below.

-----------------------------------------------------------------
PROMINENCE AND PACKAGING  (within-piece placement)   [FAIL-MB-017]
-----------------------------------------------------------------

OBJECT

SELECTION asks:
  Did outlet A omit a fact that outlet B carried, and was that fact demonstrably
  available to A when A published?

PROMINENCE asks:
  Where, inside a piece that carries the fact, was it placed? Did competing facts
  or dimensions receive materially different placement priority across headline,
  lede, and body?

These are different objects and have different evidentiary preconditions.

-----------------------------------------------------------------
EVIDENTIARY FLOOR
-----------------------------------------------------------------

A piece must be FULL-TEXT-CONFIRMED to support a prominence finding.

HEADLINE-ONLY or SNIPPET-ONLY pieces may not support a within-piece placement
finding because the hierarchy cannot be established without the whole piece.

Exclude such pieces from the prominence table. Do not mark their placement UNKNOWN.

Cross-piece availability:
  NOT APPLICABLE BY CONSTRUCTION.

Do not build, cite, or require an Availability Matrix row for a
prominence-packaging finding. The fact's presence somewhere in the piece
establishes that the piece possessed it.

A prominence candidate may compare:
- HEADLINE vs LEDE
- HEADLINE vs BODY
- LEDE vs LATER BODY, where materially relevant

A fact need not be absent from both headline and lede. Absence from a more
prominent layer under comparison is sufficient to create a candidate.

-----------------------------------------------------------------
PROMINENCE TABLE
-----------------------------------------------------------------

| Piece | Fact / dimension carried | Placement (headline / lede / body para n) | Competing fact / dimension occupying the more prominent layer | Packaging provenance | Cuts which way |
|---|---|---|---|---|---|

PACKAGING PROVENANCE vocabulary:
- CHOSEN
- INHERITED
- MIXED
- UNKNOWN

Build a row for every load-bearing or contested fact that:
- appears in Section B's per-fact table; or
- appears in Section C's contradictions; or
- directly qualifies, complicates, or reverses a figure or factual dimension
  foregrounded in the same piece.

Do not build rows for ordinary low-value facts merely because they appear lower
in the article.

-----------------------------------------------------------------
WHAT MAKES THIS A FINDING, NOT AN OBSERVATION
-----------------------------------------------------------------

Headlines and ledes cannot carry everything. Lower placement is normal and is
NOT by itself a finding.

A prominence finding requires BOTH:

  (a) MATERIALITY:
      the fact is load-bearing or contested, OR directly qualifies, complicates,
      reverses, or changes the interpretation of a competing fact/dimension
      foregrounded in the same piece;

AND

  (b) ASYMMETRY:
      EITHER:
      - different pieces foreground different sides of the same fact-pair or
        factual dimension;
      OR:
      - one piece's headline or lede foregrounds a proposition/figure that its
        own lower text materially qualifies.

Where only (a) holds, record the row and stop:

  PROMINENCE RECORDED — NO MATERIAL ASYMMETRY ESTABLISHED.

Candidate generation may be broad. Finding generation is not.
The (a)+(b) trigger is mandatory.

-----------------------------------------------------------------
PACKAGING PROVENANCE — CHOSEN / INHERITED GATE
-----------------------------------------------------------------

A prominence pattern may be observed even when inherited. But claims about
editorial or outlet choice require provenance.

CHOSEN:
  The outlet's packaging choice is independently attributable to the outlet.
  A prominence-packaging finding may describe outlet choice.

INHERITED:
  The placement pattern is inherited from a wire, common source package, or other
  upstream structure.
  Record the pattern if analytically relevant, but do NOT attribute the packaging
  decision to the outlet.
  SOURCE-CHAIN owns the inheritance explanation.

MIXED:
  Identify the chosen and inherited components separately.
  A finding may attribute only the chosen component to the outlet.

UNKNOWN:
  The prominence pattern may be described, but attribution to outlet choice is
  capped at PROVISIONAL.

A prominence finding about outlet editorial choice requires:
- CHOSEN provenance; or
- MIXED provenance with the chosen component identified.

Do not infer CHOSEN merely because the outlet has its own byline.

-----------------------------------------------------------------
FACT-TIMING / VERSION CHECK — INNOCENT EXPLANATION
-----------------------------------------------------------------

Cross-piece availability does not govern prominence, but publication/update
timing can explain why a fact appears lower in a piece than in its headline.

This is a narrower question than SELECTION:

  Could the subordinated or qualifying fact have entered the article only AFTER
  the headline was originally set?

Before attributing a prominence pattern to a deliberate same-version packaging
choice, check Section A and any already-retrieved timestamped material for:
- initial publication time;
- last-updated time;
- correction/update note;
- whether the headline changed;
- whether version history is known;
- whether the subordinated/qualifying fact demonstrably predates initial
  publication, demonstrably emerged later, or has unknown timing.

Use three states:

FACT TIMING: PREDATES INITIAL PUBLICATION
  The fact is shown by timestamped packet material, a timestamped primary source,
  or clearly earlier packet coverage to have existed before the piece's initial
  publication.
  Result:
  - later-body-update explanation is RULED OUT for that fact;
  - unknown headline-version history does NOT by itself create a same-version
    caveat.

FACT TIMING: EMERGED AFTER INITIAL PUBLICATION
  The fact is shown to have emerged after initial publication and before a later
  body update.
  Result:
  - later-body-update explanation is LIVE;
  - the observed prominence pattern remains real;
  - attribution to a deliberate same-version packaging choice is limited unless
    headline/version history resolves it.

FACT TIMING: UNKNOWN
  The available packet does not establish whether the fact predated initial
  publication.
  Result:
  - prominence remains observable;
  - same-version editorial attribution remains unresolved.

Where the later-body-update explanation is live or timing is unknown, report as
appropriate:

  PROMINENCE OBSERVED; SAME-VERSION PACKAGING ATTRIBUTION UNRESOLVED.

Do NOT convert this into a cross-piece availability failure.

Unknown version history is not an automatic caveat when fact timing already
rules out the later-body-update explanation.

-----------------------------------------------------------------
PROMINENCE SYMMETRY CHECK / PACKET INVERSE  (mandatory)
-----------------------------------------------------------------

This is NOT Section F's constructed mirror.

It is an observed inverse within the packet.

For every prominence finding:

1. State the foregrounded fact/dimension.
2. State the subordinated or qualifying fact/dimension.
3. Search the eligible comparison set for a reversed prominence relationship.
4. Classify the inverse:

   FULL
   The comparison piece materially reverses the prominence relationship at a
   comparable placement level.

   PARTIAL
   The comparison piece reverses the relationship incompletely — for example,
   the qualifying fact reaches the lede but not the headline.

   NONE
   No inverse is located in the eligible FULL-TEXT-CONFIRMED comparison set.

5. Name the inverse piece(s), where present.

Required output states:

  PACKET INVERSE: FULL — [piece(s)]
  PACKET INVERSE: PARTIAL — [piece(s)]
  PACKET INVERSE: NONE AMONG [N] FULL-TEXT-CONFIRMED ELIGIBLE PIECES

A one-directional finding where an available FULL or PARTIAL inverse exists but is
not acknowledged is incomplete and must be downgraded.

A PARTIAL PACKET INVERSE fully satisfies the symmetry requirement.
FULL / PARTIAL / NONE is descriptive and does NOT mechanically raise or lower
severity. Severity follows materiality, evidentiary support, provenance, and the
ordinary severity rules. Do not downgrade merely because the observed inverse is
PARTIAL.

-----------------------------------------------------------------
ABSENCE FLOOR FOR "NO PACKET INVERSE"
-----------------------------------------------------------------

"NO PACKET INVERSE" is an absence claim.

It therefore inherits the ABSENCE-CLAIM EVIDENCE FLOOR for the claimed comparison
range.

An unqualified packet-wide NONE claim requires every eligible source in the
claimed range to be FULL-TEXT-CONFIRMED.

If some eligible pieces are not fully retrieved, report instead:

  NO PACKET INVERSE LOCATED AMONG [N] FULL-TEXT-CONFIRMED PIECES;
  [M] ELIGIBLE PIECES EXCLUDED FROM INVERSE TEST.

Do not treat excluded snippet/headline-only pieces as evidence of absence.


SEMANTIC-GATE INTERACTION

A prominence finding must be grounded in PLACEMENT PRIORITY among substantive
facts or factual dimensions, not merely in different wording for the same fact.
If the candidate contrast is itself a lexical/formulation difference, record the
placement observation but defer any finding until the SEMANTIC EQUIVALENCE AND
EARNEDNESS GATE resolves the wording. If that gate returns REGISTER VARIANCE or
EARNED SPECIFICITY with no moved substantive assignment, the wording difference
may not anchor a prominence-packaging finding.

-----------------------------------------------------------------
RELATIONSHIP TO OTHER SECTIONS — TYPE OWNERSHIP / NO DOUBLE-COUNT
-----------------------------------------------------------------

SOURCE-CHAIN / CLAIM-AMPLIFICATION owns:
- removal or restoration of source attribution;
- removal or restoration of epistemic status;
- source-cue compression;
- packaging that is materially inherited from an upstream source/wire.

If the only headline/body difference is that the headline strips or restores
attribution, source provenance, or epistemic qualification, do NOT emit a
prominence-packaging finding for the same analytical object.

D-ROLE / CAUSAL-ROLE-FRAMING owns:
- different event-classification assignments;
- different causal assignments;
- different role/status assignments;
- different blame/responsibility assignments;
- different remedy assignments;
- different leadership/policy assignments.

PROMINENCE-PACKAGING owns:
- placement priority among substantive facts or competing factual dimensions that
  the piece itself carries without contradiction across its layers.

A single piece may support both a source-chain finding and a prominence finding
only where the analytical objects differ.

Example:

  "60,000" headline strips Vivas attribution
    -> SOURCE-CHAIN / CLAIM-AMPLIFICATION.

  "60,000" headline foregrounds gross arrivals while the same piece carries
  return context lower in the text
    -> PROMINENCE-PACKAGING.


-----------------------------------------------------------------
SEMANTIC EQUIVALENCE AND EARNEDNESS GATE   [FAIL-MB-018]
-----------------------------------------------------------------

JURISDICTION — IMPORTANT

This gate governs:

- lexical / formulation differences proposed as framing evidence;
- language-package expansion triggered by wording variance;
- VERB-AS-TRACE candidates;
- event-classification findings whose evidentiary object is a wording difference;
- D-ROLE expansion triggered by a lexical/formulation difference.

This gate does NOT govern D-ROLE's independent substantive scan.

D-ROLE must remain able to discover semantic assignment differences directly,
including differences such as:

  "smugglers caused the crossing"
  versus
  "police facilitated the crossing"

Those are substantive CAUSE / BLAME assignments even if no lexical comparison
generated them.

RULE:

  A bucketed lexical difference may not TRIGGER D-ROLE.
  D-ROLE may independently DISCOVER a substantive assignment difference.

Do not condition the six-axis causal-role scan on survival of a word-bucketing
step.

=================================================================
STEP 0 — COMPARABILITY GATE
=================================================================

Before bucketing formulations together, establish that they are actually
comparable.

Two formulations may enter the same semantic comparison only when they refer to:

- the same underlying actor / party or materially equivalent actor class;
- the same event or action;
- the same relevant object;
- the same or materially comparable evidentiary stage;
- the same or materially comparable event stage / time slice.

Do NOT normalize across real event evolution.

Examples of invalid comparisons:

- early "crossing" versus later "return";
- allegation-stage "suspect" versus post-charge "defendant" where status changed;
- "two groups firing" versus a later classification based on newly available
  evidence, unless same-stage comparability is separately established.

Where timing, referent, or evidentiary stage explains the difference, route the
object to the appropriate timing/update/same-stage logic. Do not treat it as
semantic synonym variance.

=================================================================
STEP 1 — BUILD THE COMMON BUCKET
=================================================================

For each contested or load-bearing event/action, collect the comparable
formulations used across the packet.

The unit of analysis is the SEMANTIC ASSIGNMENT, not the word.

Group formulations into one COMMON BUCKET only when:

- they describe the same underlying proposition;
- they refer to the same/comparable actor, action, object, and stage under STEP 0;
- the semantic content needed for the shared proposition is supported by the
  retrieved packet;
- they do not materially alter:
  * EVENT CLASSIFICATION
  * AGENCY
  * ROLE / STATUS
  * CAUSE
  * BLAME / RESPONSIBILITY
  * REMEDY
  * LEADERSHIP / POLICY
  * EPISTEMIC LEVEL
  * MORAL / EVALUATIVE CLASSIFICATION
  * another substantive reader model of the event.

Required compact output:

| Underlying event/action | Common bucket | Candidate specificity / outliers | Resolution |
|---|---|---|---|

Record each resolved bucket ONCE.

Do not reproduce every bucketed formulation in later sections.

=================================================================
STEP 2 — DECOMPOSE ADDED SEMANTIC CONTENT
=================================================================

Before deciding that a more vivid, specific, or forceful formulation is EARNED
SPECIFICITY or a MATERIAL OUTLIER, state what semantic content it adds beyond the
common bucket.

Required form:

  CANDIDATE: [word/formulation]
  COMMON PROPOSITION: [shared proposition]
  ADDED SEMANTIC PREDICATE(S): [what additional claim/classification the candidate adds]

Examples:

  "breach"
    common proposition:
      people crossed a boundary
    candidate added predicates may include:
      - the boundary was restricted / defended / controlled;
      - the crossing occurred contrary to that control;
      - the boundary/control was overcome.

  "riot"
    common proposition:
      public gathering / confrontation occurred
    added predicate:
      serious disorder / violence sufficient to alter event classification.

  "waved through"
    common proposition:
      people crossed
    added predicate:
      an authority facilitated or permitted the crossing.

If no additional semantic predicate can be named, the candidate is not a
material outlier. Return it to the common bucket as REGISTER VARIANCE.

=================================================================
STEP 3 — EARNED SPECIFICITY
=================================================================

A formulation with additional semantic content is EARNED SPECIFICITY — not
framing divergence — only when the added predicate is:

1. supported by material in the retrieved packet;
2. supported independently of the formulation being tested;
3. uncontested across the relevant packet material.

EARNED IS A PACKET TEST, NOT A TRUTH TEST.

The Coverage Network branch does not adjudicate what actually happened outside
the retrieved object.

"Supported" means:
  retrieved packet material provides evidence for the added predicate.

"Uncontested" means:
  no relevant piece in the packet disputes the predicate or presents materially
  incompatible evidence.

-----------------------------------------------------------------
NON-CIRCULAR SUPPORT RULE — MANDATORY
-----------------------------------------------------------------

The candidate formulation may NOT count as evidence that its own added predicate
is supported.

Neither may:
- the same word repeated by another outlet;
- a synonymous restatement that merely presupposes the same added meaning;
- an inference whose only premise is the candidate wording itself.

Support for EARNED SPECIFICITY must come from packet material independent of the
formulation being tested.

Example:

  Candidate: "breach"

  NOT sufficient:
  - AP says "breach";
  - NPR repeats "border breach";
  - CBC says "breached".

  Potentially sufficient:
  - independently reported facts describing a controlled/restricted boundary;
  - observed barrier or controlled crossing point;
  - independently described actions showing the control/barrier was overcome;
  - no relevant packet item disputes those underlying predicates.

If the only "support" for a forceful term is other outlets repeating that term,
EARNED SPECIFICITY is NOT established.

If the underlying predicate is contested among the pieces:

  DO NOT adjudicate the dispute in order to award earnedness.

The candidate remains a MATERIAL OUTLIER and proceeds to downstream evidence,
source-chain, inheritance, and assignment analysis.

Where earnedness is established, record:

  EARNED SPECIFICITY — [candidate] adds [predicate]; independently supported by
  [packet evidence]; uncontested in eligible packet material.

Then stop the lexical-framing path for that candidate.

Precision is not rhetoric merely because it is more specific.

=================================================================
STEP 4 — STOP ON ORDINARY VARIANCE
=================================================================

Formulations remaining inside the common bucket are REGISTER VARIANCE.

Record them once.

They DO NOT propagate as lexical candidates into:

- language trajectory;
- language-package expansion;
- VERB-AS-TRACE;
- lexical-triggered D-ROLE expansion;
- the flip test;
- Section H;
- Section I.

Do not re-derive, re-test, or re-report them downstream.

If every comparable formulation resolves inside the common bucket or as earned
specificity and no substantive assignment moves, write:

  SEMANTIC NORMALIZATION: [event/action] — no material assignment difference;
  wording resolved as register variance and/or earned specificity;
  language-package analysis NOT TRIGGERED by this wording object.

This is a valid and expected null result.

=================================================================
STEP 5 — CARRY FORWARD ONLY MATERIAL OUTLIERS
=================================================================

A lexical/formulation candidate advances only if its added semantic content
materially moves at least one named substantive assignment.

For every surviving outlier, state:

| Outlier | Added semantic predicate | Assignment moved | Direction of movement | Why not bucketed / earned |
|---|---|---|---|---|

An outlier with no named moved assignment is not an outlier.

Return it to the common bucket.

Surviving wording-derived outliers may then proceed to the relevant downstream
tests, including:

- VERB-AS-TRACE;
- source / wire inheritance;
- CHOSEN / INHERITED ownership;
- epistemic classification where applicable;
- same-stage checks not already resolved;
- innocent-explanation tests;
- D-ROLE where the wording genuinely moves a MEDIA-P1 assignment;
- flip/symmetry;
- standardized finding table.

=================================================================
STEP 6 — BUCKETING SYMMETRY CHECK
=================================================================

Bucketing is itself a judgment surface.

Aggressive bucketing can suppress real divergence.
Narrow bucketing can manufacture divergence.

Before finalizing the bucket, ask:

  Would these same formulations be bucketed identically if outlet identities
  were permuted?

  Would the bucket remain the same if the apparent political valence were
  reversed?

If not, rebuild the bucket.

Do not ask the model to declare which outlet it finds sympathetic or
unsympathetic.

Required output:

  BUCKETING SYMMETRY CHECK: PASS

or, if the first classification changed:

  BUCKETING SYMMETRY CHECK: REBUILT — [brief reason]

A bucket that fails the permutation/valence test may not govern downstream
suppression.

=================================================================
PROVENANCE HANDOFF — CHOSEN / INHERITED
=================================================================

This patch does NOT promote CHOSEN / INHERITED into a new shared primitive.

The recurring coupling is logged for later review.

Important distinction:

  semantic status
      !=
  provenance of the wording choice

This gate answers:
  Are the formulations semantically equivalent, earned, or materially different?

It does NOT by itself answer:
  Whose wording choice was this?

For a surviving MATERIAL OUTLIER, downstream Coverage Network provenance rules
still determine whether the wording was:

- CHOSEN
- INHERITED
- MIXED
- UNKNOWN

Do not attribute a surviving lexical choice to an outlet merely because the
semantic gate found it material.

Likewise, uniform wire inheritance does not make a material semantic difference
disappear; it changes ownership of the framing choice.

- PROMINENCE / PACKAGING;
- semantic / language analysis.

Log this recurrence. Do not independently redefine the provenance vocabulary in

UPDATE TRIGGER AND PERSISTENCE

For every significant package shift or non-shift, identify:

UPDATE TRIGGER
- What newly available fact should reasonably have caused the package to change?
- When did that fact become available?
- Was it available before the relevant headline, lede, body, or update?

PERSISTENCE
- Did the earlier package remain unchanged?
- Did it partially change?
- Did it fully change?
- Was persistence justified by uncertainty, legal limits, attribution rules,
  article format, or other SHARED INNOCENT-EXPLANATION TEST explanation?
- Did the package remain mismatched to the strongest available facts?

|---|---|---|---|---|---|

LANGUAGE PACKAGE
-----------------------------------------------------------------

For each party selected for full analysis, record:

- SOFTENING LANGUAGE
  Age-based, protective, euphemistic, minimizing, depersonalizing, or passive
  constructions.

- HARDENING LANGUAGE
  Agentive, moralized, criminalizing, pathologizing, delegitimizing, or
  categorical constructions.

- AGENCY ASSIGNMENT
  Who acts, causes, chooses, suffers, receives, or is acted upon.

- ACTIVE / PASSIVE CONSTRUCTION
  Whether grammatical form changes responsibility or role visibility.

- EVALUATIVE FRAMING
  Victimized, threatening, legitimate, illegitimate, competent, failed,
  credible, deceptive, heroic, suspect, or equivalent coloring.

- ATTRIBUTION TYPE
  Outlet voice, direct quotation, paraphrase, official allegation, source
  inference, or independently established fact.

- SPECIFICITY
  Whether categorical detail is increased, reduced, or replaced by abstraction.

- TEMPORAL UPDATE PATTERN
  Whether the package changes across updates, corrections, or related coverage.

- UPDATE TRIGGER
  The specific new fact that should reasonably have caused a change.

- PERSISTENCE
  Whether the package remains unchanged despite stronger or updated facts.

COMPOSITE ANALYSIS RULE

Do not interpret a noun in isolation.

Record the verbs, modifiers, attribution structure, sequencing, certainty,
agency, and evaluative framing that jointly construct the party's role.

A nominally soft label may coexist with strong agency and severe conduct.
A nominally hard label may coexist with protective or exculpatory framing.

Do not infer motive from package differences.

Preferred neutral descriptive wording for same-stage abstraction:

  "Reduces categorical specificity at the point of agency assignment."

Avoid "sanitizes," "launders," "disguises," or similar motive/effect language
unless independent evidence supports the claimed effect or intent.

TEST THE SOURCE OF THE UNIFORMITY - CANONICAL FIVE-WAY CLASSIFICATION

  INDEPENDENT-EDITORIAL-CONVERGENCE
    Several newsrooms reached the treatment separately.

  WIRE-INHERITANCE
    One wire story appears under multiple mastheads.

  COMMON-PRIMARY-SOURCE
    Outlets worked from the same release, briefing, document, or speaker.

  LEGAL/PROFESSIONAL-CONVENTION
    The treatment follows an identification, sub judice, privacy, or other
    professional convention.

  SHARED-BLIND-SPOT
    No outlet examined the material point.

THE STANDARD RESOLUTION TARGETS  -  check each explicitly:

  1. SOURCE-INTERNAL ORDERING (single-piece F2 Step 5). The single-piece audit could not tell
     whether an institutional source led with framing material or the outlet foregrounded it.
     TEST: how did other outlets covering the same statement order it? If most led with the
     factual account, the audited outlet's ordering was a choice. If most led with the framing
     material, the source spoke that way and the finding collapses. Also check: does any
     outlet quote or link a transcript, recording, or written release that fixes the order?

  2. VERB AND DESCRIPTOR CHOICE. The single-piece audit can only observe that a word is milder
     or more vivid than alternatives it imagines. TEST: what words did other outlets use for
     the same action - and CRITICALLY, what word does the PRIMARY SOURCE use? An institution
     often issues both a written release and a spoken briefing, and they frequently differ. A
     verb that looks like editorial softening may be DOCUMENT DEPENDENCE: the outlet used the
     presser, another outlet used the written report. Then route the surviving difference
     through [MEDIA-P1]. Apply VERB-AS-TRACE (compact primitive) only if the
     wording survived the Semantic Equivalence and Earnedness Gate as a MATERIAL
     OUTLIER; otherwise the lexical object is already resolved upstream. If the
     surviving wording moves an assignment, use it as evidence for a causal-role-framing
     finding. Both branches now emit findings in the [MEDIA-P1] vocabulary, so D2 lines them
     up directly rather than translating between two axis sets. Resolution therefore works
     regardless of which branch was the entry point. If document dependence explains the
     wording, the single-piece finding is not outlet construction - it is a
     sourcing-thoroughness observation and must be reclassified. Say so plainly.

  3. AVAILABILITY OF A BALANCING VOICE. The single-piece audit cannot tell whether a
     counter-voice was unavailable, refused, or unsought. TEST: did any outlet in the sample
     obtain one? If several did, availability is established and the single-piece finding
     strengthens. If NONE did, the absence is network-wide and is weak evidence about any one
     outlet.

  4. HEADLINE CHOICES. The single-piece audit judges a headline against the
     body. TEST: what did every other headline include and omit? If EVERY outlet
     made the same omission, downgrade the claim that the audited outlet is
     distinctive or uniquely slanted. Do NOT automatically downgrade the
     underlying construction finding; resolve it as NETWORK-WIDE and classify
     the source of uniformity.

  5. OMISSION vs. CONVENTION. Any fact the single-piece audit flagged as omitted. TEST: who
     else omitted it? A fact omitted by every outlet, especially one sitting in a primary
     document all of them had, is a NETWORK-WIDE pattern. That is a different and often more
     interesting finding than an outlet- specific one  -  and it is not evidence of that
     outlet's lean.

| Single-piece finding | What it flagged as undeterminable | What this sample shows | Resolution |
|---|---|---|---|

RESOLUTION values  -  use exactly these: CONFIRMED ......... the sample supports the
single-piece finding; it strengthens FALSIFIED ......... the sample shows the finding was
wrong; it must be CUT RECLASSIFIED ...... real, but a different finding type than originally
rated NETWORK-WIDE ...... the behavior is shared across outlets. This establishes the outlet

inherit the same official euphemism, wire framing, legal convention, or blind spot. DOWNGRADE
the claim that this outlet is distinctive. DO NOT DOWNGRADE the underlying construction

EVIDENCE FLOOR  -  MANDATORY. CONFIRMED, FALSIFIED, RECLASSIFIED, and NETWORK-WIDE each
require you to NAME THE SPECIFIC EVIDENCE in the resolution cell: which outlet, which
document, which passage. A resolution without named evidence is not a resolution.

  If you did not retrieve material bearing on the item, the ONLY permitted values are STILL
  UNRESOLVED or NO EVIDENCE.

  CONFIRMED IS THE MOST DANGEROUS VALUE HERE. It ratifies an upstream finding, and it is the
  value most easily returned by a run that simply did not look. Absence of contradicting
  evidence is NOT confirmation. If your basis for CONFIRMED is "nothing I saw contradicted
  it," the correct value is STILL UNRESOLVED.

  Worked contrast, from actual runs of this prompt on the same event: asked whether an outlet
  reordered a police chief's statement, one run returned CONFIRMED having obtained no primary
  source; another returned FALSIFIED citing a specific outlet's report that the chief opened
  his briefing that way; a third returned STILL UNRESOLVED, lacking that outlet. Only the
  second and third were defensible.

REPORT FALSIFICATIONS PROMINENTLY. A finding this branch kills is the most valuable output the
system produces  -  it is the only place a claim gets tested against evidence rather than

why, and what the evidence was.

NOTE ON DIRECTION: this section will more often WEAKEN single-piece findings than strengthen

single-article reading suggests. That asymmetry is expected and is not a sign the section is
malfunctioning. If it never weakens anything across multiple runs, it is not doing its job.

SECTION F  -  FLIP TEST  (MANDATORY  -  DESIGNED TO BE COSTLY)
=================================================================

Answering "yes, I would flag the mirror" is free. This section requires producing something.

STEP 1  -  WRITE THE MIRROR, AS TEXT Take your #1 divergence finding. COMPOSE the actual
mirror  -  3-6 sentences of a headline plus lead written the way an outlet in the opposite
cluster would have written it, using the same technique you flagged. Not a description. The
text.

STEP 2  -  AUDIT YOUR OWN MIRROR Run your Section D criteria against what you just wrote.
Produce at least two findings against it with severity ratings. If you cannot produce findings
at comparable severity, your original finding is PRIOR-DEPENDENT  -  downgrade it.

STEP 3  -  CONSISTENCY CHECK Compare the PRINCIPLES you applied to your mirror against your
findings on the real coverage. Classify what you find  -  two different things, resolving
oppositely:

  (A) INCONSISTENT PRINCIPLE  -  you applied a rule to the mirror you did not apply to the
  original, or vice versa. One finding must give; state which and why. Mirror-side principles
  are less prior-contaminated (applied without knowing which side benefited), so they usually
  win.

  (B) SYMMETRIC PHENOMENON  -  the same construction lever appears in both, pushing opposite
  directions (e.g. either ordering constructs an impression). NO DOWNGRADE. This confirms the
  lever is a construction lever, which makes the outlet's specific choice more meaningful, not
  less.

  DO NOT DOWNGRADE BECAUSE THE MIRROR COMMITS THE MIRROR-IMAGE VERSION. That is the expected
  result and the reason the mirror exists  -  it tests whether you apply the same rule, not
  whether construction is universal.

| Observation | Type (A / B) | Resolution |
|---|---|---|

Downgrades are permitted here for TYPE A only.

STEP 4  -  FORCED RANKING Rank all findings from MOST prior-dependent to LEAST.

| Rank (1 = most prior-dependent) | Finding | Why more prior-dependent than the next |
|---|---|---|

STEP 5  -  AUTOMATIC DOWNGRADE  (not discretionary)

The finding ranked #1  -  MOST prior-dependent  -  IS DOWNGRADED ONE SEVERITY STEP.
Mechanical. No justification path, no opt-out.

  MAJOR -> MODERATE / MODERATE -> MINOR / MINOR -> cut or "reported, not load-bearing"

Earlier versions allowed declining the downgrade with a rebuttal. The rebuttal was always
supplied and the downgrade never happened. A check that can be argued away is not a check.

IF THE DOWNGRADE SEEMS WRONG, FIX THE RANKING IN STEP 4  -  you control it. Do not argue with
the consequence. Do not append a parenthetical rebutting it.

State in one line: "Downgrade applied: [finding] MODERATE -> MINOR." Report in Section I which
finding was downgraded and from what to what.

=================================================================
SCOPE LIMITS  -  RESTATE IN OUTPUT
=================================================================

  1. Coverage distribution is not a truth verdict. Majority framing is not
     evidence of accuracy, particularly where a load-bearing proposition is
     source-dependent, claim-amplified, or has unresolved origin completeness
     in Section B.
  2. One event does not establish an outlet's practice. That requires a corpus across events
     -  a different and larger audit.
  3. Divergence does not establish intent. Editorial choice is observable; motive is not.
  4. Wire dependence, length, and deadline explain substantial variance. Test them before
     attributing divergence to lean.
  5. A convenience sample supports findings about the pieces examined, not about coverage
     generally.
